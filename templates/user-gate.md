# 拍板卡（User Gate 模板 & 速查表）

> 规则：**制片人每次向用户（甲方）拍板，必须用 ask_user_question 且带选项卡**——≥2 个选项、推荐项放第一位并标注"(Recommended)"、需要时允许多选、**永远留一个"自定义/我来补充"兜底选项**（用户选它时再追问）。禁止开放式提问；**也禁止用纯文本列 A/B/C 呈现选项**——任何让用户选择的场景（拍板点/对话中请用户决定的事项）一律选项卡。唯一例外：纯信息收集且无法枚举时，也先给可选项+兜底。

> **证据先行（硬规则，最重要）**：**基于项目文件/产物的一切拍板，必须先把内容展示给用户，再给选项卡**——用户看不到依据就选择=盲选，禁止。
> - **文本类依据（口播稿/方案/分镜表/prompt 表/理解报告）**：拍板前完整展示——口播稿贴**全文**；方案贴定位/受众/分镜概览/执行计划四段要点；分镜表贴**全部行**；prompt 表贴全部段或代表作+段清单；理解报告贴"两点讲明"+关键数据+来源清单。
> - **图片类依据（九宫格/首帧图/参考图）**：给**完整路径** + 逐格/逐张描述（构图/主体/配色/光效/用途），并在对话中贴出图片（宿主支持时）；用户可打开文件复核。
> - **数据/来源**：贴引用出处（论文/URL/官方文件）。
> - 展示顺序：**证据区块 → 问题 → 选项**，同一轮内完成；用户说"我自己看文件"时给路径即可。

## 卡结构

```
标题: <一句话决策名>
问题: <1-2 行: 我们在……，需要你拍板：>
选项:
  1. <方案A> （Recommended）  <一句话理由/代价>
  2. <方案B>  <一句话理由/代价>
  3. <自定义/等信息>  <兜底>
```

> 预置选项是"默认弹药"——制片人必须按项目实际情况改写选项文本（带项目具体信息），速查表只保证"每个拍板点都有选项可给"。

## 与流程的关系

- 拍板卡 = 关卡（M1/M3/M5 必用；M2/M4 出口按档位用），跑完才允许进入下一里程碑（见 `orchestration/ORCHESTRATION.md` §4）。
- 用户选择"自定义"时：追问 1 轮 → 仍无法枚举 → 才转为书面开放式提问（模板见 `templates/brief.md`）。
- 红队三态裁决的 PASS/CONDITIONAL/BLOCK 必须转成拍板卡（见速查表 #11/#12），不能直接甩评审意见给用户。
