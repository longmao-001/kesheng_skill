# 科生 v2 · 多 agent 协作重构设计

> 版本 v2.0 (2026-09)。目标：把科生从"单 agent 分饰多角的角色扮演"重构为**真多 agent 协作**——每个角色是独立上下文的 agent，各有专责、并行开工、制品交接、门控把关。
> 参考依据：本机 DeepSeek Harness (DSH) 的 subagent/workflow/subagent_fork 机制（Atelier 已在生产中使用，见 `f:/AI/atelier/docs/DSH_ORCHESTRATION.md`）+ 业界多 agent 编排方法（见 §1）。

## 0. 现状问题

| 问题 | 表现 |
|---|---|
| 角色是"演"的，不是"是"的 | SKILL.md 默认"单助手扮演全部角色"：7 个角色共用 1 个上下文，制片人和红队是同一个人，盲提案不盲、对抗不抗 |
| 上下文相互污染 | 编剧写完的用词会"传染"科学顾问的表述；红队还没看方案就知道结论方向（锚定效应） |
| 责任过载 | 一次生成要同时满足科学准确+叙事+视觉+p prompt 语法+受众适配，单上下文顾此失彼 |
| 没有真并行 | 调研、提案、转写全是串行推演，实际耗时=所有角色之和 |
| 会议纪要给"自己的分身"确认 | 无独立上下文，假共识无法被真正打破 |

## 1. 参考的多种方法（调研与选型）

| # | 方法 | 核心机制 | 成本 | 适用场景 | 在科生哪里用 |
|---|---|---|---|---|---|
| 1 | **层级式 Orchestrator–Workers**（OpenAI Agents SDK / Supervisor 模式） | 一个主控 agent 拆解任务、分派 worker、汇总裁决，worker 各自独立上下文 | 单层并行，成本≈串行之和 | 角色职责清晰、可拆子任务的工作流 | 全局骨架：制片人=主控，7 角色=worker |
| 2 | **流水线 SOP / Handoff**（MetaGPT 式） | 定义阶段产物格式，阶段间只交接制品，前阶段输出=后阶段输入 | 线性，每阶段 1 agent | 强前后依赖、强格式约束 | M5→M6 链路：简报→理解→方案→分镜→prompt 顺序交接 |
| 3 | **多角色辩论 Debate / MAD**（Du et al. arXiv:2305.14325；MAD arXiv:2305.19118） | 盲独立提案 → 交叉质询 → 立场更新 → 按预注册标准裁决 | ≈15× 单聊，最贵 | 高价值多视角决策点 | 仅 **M3 方案全会**：盲提案×3 → 交叉质询 → 裁决 |
| 4 | **生成者–批判者 / 红队闸**（Generator–Critic；Anthropic Reviewer 实践） | 独立上下文评审者只读成品+标准，输出 pass/fail 与打回意见，≤N 次循环 | 1 次额外调用 | 任何出口的硬性质量把关 | M4 前置拦截闸 + M5 出口评审闸（红队角色） |
| 5 | **黑板/共享工件库 Blackboard**（Anthropic 多 agent 系统"制品落盘轻引用"） | 所有 agent 写同一工坊目录；会议只传"路径+摘要+置信度"，不传全文 | 省 token，防"电话游戏" | 上下文隔离 + 长文档协作 | 全局：`runs/<项目>/` 工坊目录；📤 交接块=轻引用 |
| 6 | **DAG 扇出 fan-out**（DSH `workflow` 工具：并行阶段+屏障） | 无依赖子任务同批并行，屏障后合并 | 真并行，墙钟时间最短 | 调研 fan-out、批量转写 | M2 并行调研（3-5 路）、M4 prompt 分段并行转写 |
| 7 | **交叉验证 fork**（DSH `subagent_fork`：继承对话的复核者） | 用下游角色的独立上下文复核上游制品，互不知晓对方结论 | 低 | 事实性/一致性风险复核 | 科学顾问复核 prompt 表的科学表述；制片人 fork 复核争议条款 |
| 8 | **显式停滞检测**（Magentic-One 双账本） | 任务账本+进度账本；连续无新论点/无改动 → 机械判定停滞 → 重分解或升级 | 零成本 | 防无限辩论、防空转 | 制片人每场会机械执行 |

**选型结论：混合架构** —— 层级式(1)为骨架 + 黑板(5)为协作介质 + 里程碑内 fan-out(6) 与 fork 复核(7) + 流水线(2) 管里程碑间交接 + 辩论(3) 只保留在唯一值得的 M3 + 红队闸(4) 守住出口 + 停滞检测(8) 防空转。

## 2. 架构总览

```
                        ┌────────────────────────────┐
                        │  用户（甲方）── 关卡：确认/拍板 │
                        └───────────┬────────────────┘
                                    │ ask_user_question
┌───────────────────────────────────▼───────────────────────────────┐
│ 主 agent = 制片人（orchestrator，唯一"看得见全局"的角色）            │
│  职责：简报/预注册标准/定档/拆任务/派活(parallel)/汇总裁决/双账本/升级 │
└──────┬───────────┬──────────────┬──────────────┬───────────┬──────┘
       │subagent   │subagent      │subagent      │subagent   │subagent
┌──────────────────────────────────────────────────────────────────────┐
│ worker subagents（真实剧组建制，独立上下文，并行派活）                  │
│ 导演 · 编剧 · 分镜师 · 美术指导 · 摄影指导 · 声音设计师 · 剪辑师        │
│ 科学顾问 · prompt工程师 · 观众代言人 · 红队（闸点触发）                 │
└──────────────────────────────────────────────────────────────────────┘
       │ 红队=制度性反对者（M3 对抗 / M4 前置闸 / M5 出口闸）
                        ┌────────────────────────────┐
                        │ 黑板 = runs/<项目>/ 工坊目录 │  ← 所有 agent 读写
                        │ brief/m2/proposals/m4/logs │  ← 只传轻引用📤
                        └────────────────────────────┘
```

**关键原则**
1. **制片人不写内容，只编排**——它派活、汇总、裁决、升级；唯一例外是 S 档降级（见 §4）。
2. **每个角色独立上下文**：用 DSH `subagent`（默认后台=并行），prompt 模板见 `orchestration/ORCHESTRATION.md` §1。
3. **黑板轻引用**：agent 间只传"路径+3 条摘要+置信度自评"，全文在工坊文件里。
4. **会议与干活分离**：并行干活（隔离上下文）→ 打架只在裁决点（制片人读📤统合，或交叉质询轮）。
5. **门控必须来自独立上下文**：红队不参加创作，只读制品+预注册标准。

## 3. 里程碑编排总览

| 里程碑 | 参与 agent | 机制 | 并行 | 门控 |
|---|---|---|---|---|
| M1 简报 | 制片人（主）+ 科学顾问/导演/摄影指导/观众代言人 4 worker | 问卷→预注册标准定稿；4 worker 各交一页清单（科学硬约束/艺术基调/可拍约束/受众证据模型） | ✅4 路 | 用户确认简报卡 |
| M2 科学理解 | 科学顾问主 + 观众代言人（受众语境）+ 导演（艺术基调/可拍性），可扩 5 路 | fan-out 深入调研，制品入库 m2/ | ✅3-5 路 | 理解深度 ≥L2，待确认项有去向 |
| M3 制作方案 | 编剧/分镜师/摄影指导/导演 4 提案 + 交叉质询 + 红队 | **唯一全会**：盲提案→质询→导演整合 v1→制片人按预注册标准复核裁决 | 提案并行→质询并行→整合串行 | 纪要+少数派报告交用户确认 |
| M4 分镜+prompt | 编剧（口播稿）→(分镜师‖声音设计师)→摄影指导→prompt 工程师×N 段（转写）‖剪辑师（预计划）→美术 VI 复核→科学顾问（涉科学镜头）→红队（前置闸） | 流水线串行 + 按段 fan-out 转写（workflow 或并行 subagent） | 转写/声音/剪辑并行 | 前置闸 pass/fail（硬性违规）；M4 出口清单 |
| M5 制作交付 | 制片人陪跑 + 红队出口闸 + 科学顾问终审 + 知识萃取 | 出口评审闸=独立上下文 Reviewer 打分，≤2 次打回 | — | PASS/CONDITIONAL/BLOCK + 用户签收 + kb 萃取 |

## 4. 三档成本分级（立项时定档，写进简报卡）

| 档 | 触发 | 用哪些机制 |
|---|---|---|
| **S 档 轻量** | 简单科普短片、已有成稿只缺 prompt、纯咨询问题；用户明确要快速回答 | 制片人单干（原单机模式保留为降级档），不派生 subagent（参照"何时不用 subagent"） |
| **M 档 标准（默认）** | 一般科研/产品视频（≤5 分钟，单平台，素材已有） | 里程碑内并行 worker + 制片人裁决 + 红队前置闸 + 出口闸；不开全面对抗会 |
| **L 档 旗舰** | 申报片/融资片/多平台版本//多素材复杂项目；用户要求"全自动跑完" | 全部机制：M3 全开对抗 + 交叉质询 + 双红队闸 + 全自动 `kesheng_workflow.js` |

定档规则：M1 简报卡里由制片人按上述触发条件机械判定，并记录"档位→用了哪些机制"。

## 5. 反假共识与铁律（跨 agent 必须遵守）

1. **科学准确铁律贯穿所有对话**：数据有出处；不确定标"待确认"；绝不编造。制片人不得以"赶时间"豁免。
2. **盲独立立场先行**：任何"方案对决"前，各角色独立提交，不共享中间结论。
3. **预注册标准**：任何提案/裁决/评审先定标准（简报卡第 8 项），评审引用标准编号，不许凭感觉。
4. **异议配额**：M3 全会 ≥3 条实质异议被提出并解决；少则视为假共识，加红队一轮。
5. **少数派报告原样入纪要**：红队/异议意见即使被否也必须记录，不许"和稀泥"。
6. **事实争议不许折中**：谁对谁错=查证或升级用户，不允许"各打五十大板"。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| subagent 上下文过小读不完长制品 | 黑板轻引用+分段产出；角色卡要求"按需读取资源，不要一次性全读" |
| 并行 agent 相互冲突（同写一文件） | 文件名规约：`<角色>-<制品>.md` 唯一归属；汇总由制片人独写 |
| 转写/调研 agent 中途失败 | 重派 1 次；再失败制片人接手该子任务并记录降级（降级模式要明示用户） |
| 成本失控 | §4 三档定级；M3 全会是唯一"值 15×"的点，每场会前制片人自问"值不值" |
| 用户等太久（每关卡询问） | 关卡式 vs 全自动模式由用户选择：默认关卡式；用户说"全自动跑完"则走 `kesheng_workflow.js` |
| 科学事实漏洞穿过所有闸 | 双闸制（M4 前置闸 + M5 出口闸）+ L2 底线 + 事实争议强制升级 |
