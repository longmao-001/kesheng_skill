# 素材文件类型 · 固定处理方案（Asset Types SOP）

> **用途**：客户丢来的文件五花八门（视频/图片/矢量/PPT/PDF/Word/CAD/SolidWorks/SketchUp/3D 中性格式/字体/表格/音频），
> 本文件规定**按文件类型的固定处理动作**——每种类型「拿来干什么 → 怎么把内容弄出来 → 归到哪一类 → 命名 → 红线」。
> **定位**：`playbooks/asset-library-flow.md`（五步闭环：收集→分类→入库→建库→选片）的**前端细化**；
> 提取完之后**全部汇入同一套后端**（两轴分类 + 命名 + 三件套 + 台账 + 8 维选片），不做第二套。
>
> **铁则**：① **文件名=条目ID** ② 每张入库必做**三件套**（多模态拆解 + 反推AI提示词 + 质量分★）③ **合规一票否决**（水印/竞品/团队照/未授权不入库）④ **原图不一定出镜**（CT 类只作内容依据，后期重绘）。

---

## 〇、总原则：分类型提取（前端）→ 统一入库（后端）

```
任何文件到手
   │
   ├─ 1. 判断角色（决策树，见 §一）
   │
   ├─ 2. 按类型提取（§二 类型矩阵：各类型提取动作不同）
   │        └─ 提取时同步：分类 + 命名 + 记来源/授权
   │
   └─ 3. 汇入统一后端（所有类型同一套，见 §三）
            三件套（read_image 拆解 + 反推AI提示词 + 质量分★） → assets-inventory.md 台账
            → 选片（templates/reference-selection.md 8 维） → @图进 prompt
```

**只有"提取"这一步因类型而异；分类、命名、入库、选片全类型统一。**

## 一、决策树：这个文件拿来干什么？（提取前必答）

| 问 | 若"是" | 归类 | 处置 |
|---|---|---|---|
| 真实画面能**直接入镜**？ | 信任主体 | **IN**（直接入镜） | 直接剪入成片（须真素材+授权） |
| 给模型做**锚**（外观/结构/场景/质感）？ | 参考资产 | **RF**（参考图） | 进参考包/三视图/首帧；须真实结构或官方源 |
| 只作**内容依据**（数据/原理/图表）？ | 内容参考 | **CT**（内容参考） | 后期重绘；**原图永不出镜** |
| 只作**事实/口径**依据？ | 事实来源 | 抽取稿/报告 | 进 `refs/` 抽取稿 + scientist 报告，带出处 |

> 同一个文件可以**同时**承载多种角色（如 PPT 里既有产品外观图→RF，又有规格表→CT，又有正文→事实）：**拆开分头归类**，不要整份文件只归一类。

## 二、类型矩阵：按文件类型的固定处理动作

### 通用红线（所有类型共有）
- **来源+授权必标**：每份来源登记（客户提供/官方公开页/自采/网图）；网图**无授权只作参考构图/结构理解，绝不入镜**。
- **敏感内容不入库**：客户机密页/涉密数据/内部结构敏感尺寸 → 只作内容理解，**登记引用不存图**。
- **不得凭文件名判断**：图片类一律 `read_image` 看真图再拆解（F-13）。

---

### 1. 视频 `.mp4 / .mov / .avi / .mkv / .webm`

| 项 | 固定动作 |
|---|---|
| **定位** | `IN` 直接入镜主力（真实素材=信任度最高）；也作场景参考源 |
| **提取** | ① 读**中帧/关键帧**（`read_image`）判断内容 → ② **抽帧**建 `RF_SCENE_*` 场景参考图 → ③ 记元数据：分辨率/**画幅**/帧率/时长 |
| **归类** | 本体 `IN_RAW`；抽帧 `RF_SCENE` |
| **命名** | `IN_RAW_<主体>_<视角>_<序号>.mp4`；抽帧 `RF_SCENE_<场景>_<内容>帧_<序号>.png` |
| **红线** | ①**竖屏→16:9 必须重构图**（不许拉伸/留黑边）②**素材已带品牌角标的镜头，成片勿再叠 logo（双 logo 红线）**③高帧率/超长素材作 `★3` 备用④水印/竞品/未授权不入镜 |

### 2. 图片 `.png / .jpg / .jpeg / .webp / .tif / .heic`

| 项 | 固定动作 |
|---|---|
| **定位** | `IN`（实拍/官方渲染）/ `RF`（参考图）/ `CT`（图表） |
| **提取** | `classify_assets.py` 分类+命名 → `read_image` **三件套**（多模态拆解 + 反推AI提示词 + 质量分★） |
| **归类** | 两轴（用途 × 类型） |
| **命名** | `<用途>_<类型>_<主体>_<视角>_<序号>.<ext>` |
| **红线** | ①须标注 **实拍 / 渲染 / CG / AI**（"实拍:是" vs "渲染"）②水印/竞品/未授权一票否决③分辨率不足者仅作参考不作首帧 |

### 3. 矢量图 `.svg / .ai / .eps / .cdr / .pdf(矢量页)`

| 项 | 固定动作 |
|---|---|
| **定位** | `BRAND`（logo/VI，最常用）/ `CT`（原理示意/图表） |
| **提取** | ①**光栅化 300dpi+** 才能喂模型（矢量不能直接进 AI 工作台）②**保留矢量源**给落版/后期用（清晰无损）③**从矢量取官方真实色值 HEX**（落版/色板依据） |
| **归类** | `IN_BRAND_*` / `RF_*` / `CT_*` |
| **命名** | `IN_BRAND_<品牌>_<版本>_<序号>.<ext>` |
| **红线** | ①**禁止自造色值**（品牌色一律官方源取，防"海军金"类反模式）②logo **用字/版本须用户拍板**（如"无股票代码版"）③商标原理图示**禁作参考喂模型**（埋雷） |

### 4. PPT `.pptx / .ppt / .key`

| 项 | 固定动作 |
|---|---|
| **定位** | **素材富矿**：产品外观/结构接口/原理示意/数据图表/应用场景多藏于此；正文=事实依据 |
| **提取** | `python-pptx` 遍历 slide→shape：**抠所有图**（`shape.image`）+ **文本框**（事实/口径）+ **表格**（数据）+ **图表**；按"产品外观/结构接口/原理示意/数据图表/应用场景"分类入库 |
| **归类** | 图 → RF/CT；正文 → 事实（进抽取稿） |
| **命名** | 抠出图按内容分类命名（见 §二.2） |
| **红线** | ①PPT 图多为**拼版/带文字覆盖/低清/带水印** → 多数只能作 `CT`/参考，**不能直接作首帧**②**数据图表只作内容参考、永不出镜**③客户敏感页不入库④"演讲备注"里的事实**须核原文**才可引用 |

### 5. PDF `.pdf`

| 项 | 固定动作 |
|---|---|
| **定位** | **事实+图双重来源**（规格书/手册/论文/申报书） |
| **提取** | `PyMuPDF`：①`page.get_images()` 抠图 ②`page.get_text()` 抽文（→ `refs/<项目>_抽取稿.md`，**标页码出处**）③判断敏感页 |
| **归类** | 图 → RF/CT；文字 → 事实/口径 |
| **命名** | 图按内容分类；抽文稿统一 `refs/` |
| **红线** | ①**规格书数据是事实权威**：须**目检原文**（"大概率"不算证据），逐条记 `Typ./NA/Min` 等条件②**扫描件无文字层 → 需 OCR**③论文图表有版权 → 只作 CT④型号数字与参数数字**撞车须规避**（如型号含"4"与 4W） |

### 6. Word `.docx / .doc`

| 项 | 固定动作 |
|---|---|
| **定位** | 事实/口径（方案正文、SOP、旁白参考） |
| **提取** | `python-docx`：抽全文 + `inline_shapes` 抠内嵌图 |
| **归类** | 文字 → 事实/抽取稿；内嵌图 → RF/CT |
| **红线** | 同 PDF（出处+目检）；客户敏感段落不入库 |

### 7. CAD `.dwg / .dxf`

| 项 | 固定动作 |
|---|---|
| **定位** | `STR` 结构/尺寸参考（**一般不入镜**） |
| **提取** | **本环境无 DXF/DWG 解析库** → 走**导出**：客户侧或用转换器导出 **PDF/SVG** → 再光栅化 → 作结构参考 |
| **归类** | `CT_STR_*` |
| **命名** | `CT_STR_<结构名>_<视图>_<序号>.png` |
| **红线** | ①**CAD 不能直接喂 AI**（须先导出+光栅化）②**工程线稿≠外观**：只能让模型理解"结构关系"，**不能当外观锚**③**尺寸数字可能是敏感数据**，入镜前须核对④与实物不符时以实物/官方图为准 |

### 8. SolidWorks `.sldprt / .sldasm / .slddrw`

| 项 | 固定动作 |
|---|---|
| **定位** | **产品锚最佳来源**（3D 模型 → 可导出标准三视图/渲染图） |
| **提取** | ①工程图 `SLDDRW` → 导出 **PDF → PNG**（正/侧/背/45° 三视图）②`PhotoView 360` 渲染写实图 ③或导 **STEP/IGES** → Blender/KeyShot 渲染 |
| **归类** | 三视图/渲染 → `RF_MAIN_*`（主体锚，跨镜复用）；也可 `IN` 若渲成写实 |
| **命名** | `RF_MAIN_<产品>_<视图>_<序号>.png` |
| **红线** | ①**需 SolidWorks 环境（多在客户侧）**——须明确向客户要"导出三视图/渲染图"，不要等模型②导出须**去掉内部结构与敏感尺寸**③渲染风格须**与实拍统一**（否则与真机镜头打架） |

### 9. SketchUp `.skp`

| 项 | 固定动作 |
|---|---|
| **定位** | `SCENE` 空间/比例参考 |
| **提取** | SU 导出场景图/等轴测/漫游帧 → PNG；或导 OBJ/STEP → 渲染 |
| **归类** | `RF_SCENE_*` |
| **命名** | `RF_SCENE_<场景名>_<视角>_<序号>.png` |
| **红线** | **白模/线稿风格 ≠ 实拍风格** → **只作空间与比例参考，绝不作外观锚** |

### 10. 3D 中性格式 `.step / .stp / .iges / .igs / .obj / .fbx / .stl / .glb`

| 项 | 固定动作 |
|---|---|
| **定位** | 跨软件渲染源（拿到即可自行出图） |
| **提取** | 导入 Blender/KeyShot → 渲染**三视图/等轴测** |
| **归类** | `RF_MAIN_*` |
| **命名** | `RF_MAIN_<产品>_<视图>_<序号>.png` |
| **红线** | 需渲染环境（本环境无 trimesh）；内部结构须去除 |

### 11. 字体 `.ttf / .otf / .woff`

| 项 | 固定动作 |
|---|---|
| **定位** | 落版/数据卡用字 |
| **提取** | 登记字体名+来源；落版用字须**与品牌 VI 一致** |
| **红线** | **商用授权须核查**（字体侵权高发）；无授权改用系统/开源可商用字体 |

### 12. 表格 `.xlsx / .csv`

| 项 | 固定动作 |
|---|---|
| **定位** | 数据依据（进数据卡/图表层） |
| **提取** | 读表 → 提取**要在片上呈现的少数指标**（领导版只留 3-5 个） |
| **红线** | **数据一律人工锁值**（数据卡字卡图，**AI 不生成数字**）；未验证指标标"方案口径"或不入；口径不同**不并列同屏** |

### 13. 音频 `.wav / .mp3 / .m4a`

| 项 | 固定动作 |
|---|---|
| **定位** | 声音方案参考（BGM 参考/配音样本/现场底噪） |
| **提取** | 听辨登记（曲风/情绪/时长/有无版权）；交声音设计师 |
| **红线** | **商用授权须核查**；客户提供的配音样本≠可商用 BGM |

## 三、统一后端：提取完之后（全类型同一套）

1. **分类**：两轴 `IN/RF/CT` × `MAIN/PART/SCENE/TEXT/STR/DATA/BRAND/RAW`（`templates/assets-inventory.md` §一）
2. **命名**：`<用途>_<类型>_<主体>_<视角>_<序号>`，**文件名=条目ID**（引用一律用文件名）
3. **智能入库三件套**（每张必做）：
   - `read_image` **多模态拆解**（物品/任务/场景/结构/质感/数据/品牌/实拍）
   - **反推 AI 合成提示词**（文字检索键，可复用生成）
   - **质量分 ★1-5**（清晰度.25/主体完整.25/构图.15/光影.15/用途匹配.20；**合规一票否决**）
4. **建台账**：`assets-inventory.md`（条目ID/用途/类型/主体/视角/内容标签/反推prompt/★/来源·授权）
5. **选片**：`templates/reference-selection.md` 8 维打分 → 入选 ≤3 张 → 标"角色+部位对应+位置+依据口播句" → `@图N` 进 prompt

> **生成资产**（AI 出的图/视频）另用命名：`<项目>_镜<号>_<内容>_<版本>`（如 `R2_镜02_出光口特写_首帧.png`）。

## 四、本环境工具可用性（决定哪些能自动、哪些必须人工/外导）

| 能力 | 可用 | 说明 |
|---|---|---|
| PDF 抠图/抽文 | ✅ `PyMuPDF`(`fitz`) | `page.get_images()` / `page.get_text()` |
| PPT 抠图/抽文 | ✅ `python-pptx` | 遍历 slide/shape/table/chart |
| Word 抠图/抽文 | ✅ `python-docx` | 全文 + `inline_shapes` |
| 图像处理 | ✅ `PIL` / `numpy` / `opencv` | 光栅化/裁切/缩放/抽帧 |
| 视频抽帧 | ✅ `opencv`(`cv2`) | 读中帧/关键帧 |
| DXF/DWG 解析 | ❌ `ezdxf` 未装 | **须客户/转换器导出 PDF/SVG** |
| 3D 网格解析 | ❌ `trimesh` 未装 | **须 Blender/KeyShot 等外部渲染** |

> 缺库**不要硬造**：CAD/3D 一律走"**向客户要导出件**（三视图/渲染图/PDF）"或外部工具，作为**素材缺口**走拍板（`templates/user-gate.md #7`）。

## 五、自检（每批素材处理完过一遍）

- [ ] 每个文件都过了**决策树**（IN/RF/CT/事实四问），该拆开的已拆开分头归类
- [ ] 视频：竖屏已规划重构图；**带角标素材已标注"勿叠 logo"**
- [ ] 矢量：已光栅化进库 + 保留矢量源；品牌色**取自官方源**（非自造）
- [ ] PPT/PDF/Word：已全量抠图 + 抽文标出处；数据图表标"**永不出镜**"
- [ ] CAD/3D：已向客户要导出件（或外部渲染），未硬用原始工程文件喂模型
- [ ] 每张入库：分类 ✅ 命名 ✅ **三件套齐**（拆解/反推prompt/★）✅ 来源·授权 ✅
- [ ] 合规：水印/竞品/团队照/未授权 **全部未入库**；敏感页只登记不存图
- [ ] 台账 `assets-inventory.md` 已更新；选片待用
- [ ] 跑门控：`python -X utf8 scripts/check_asset_pack.py <runs/<项目>>`（引用可解析 + 无后补提示词）
