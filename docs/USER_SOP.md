# 科生 · 用户使用流程规范（User SOP · KSP-01~07）

> 版本 v1.0（2026-09）。**用户使用科生时的唯一规范流程**。制片人（主 agent）必须按本流程机械执行：步骤顺序、门控判定、拍板卡交互均不得跳步；例外见 §8 降级通道。
> 配套：`docs/ROLE_WORKFLOWS.md`（角色 SOP）、`orchestration/ORCHESTRATION.md`（派活清单）、`templates/user-gate.md`（拍板卡速查）、`protocols/quality-gate.md`（出口标准）。

## 0. 三条铁则

1. **用户是甲方**：每关结束必须经用户拍板（选项卡）才能推进；未经拍板不得进入下一阶段。
2. **拍板必须选项卡**：一律 `ask_user_question`，≥2 选项、推荐置顶"(Recommended)"、可多选、必留"自定义"（`templates/user-gate.md`）。
3. **证据先行**：基于项目文件的拍板，**先展示文件内容再给选项**（文本贴全文/要点，图片给路径+描述+贴图，数据给来源）；用户看不到依据=盲选，禁止。
4. **知识只进图谱**：任何调研/验证知识 → 域片段 → 重建图谱，不新建概念卡（`orchestration/ORCHESTRATION.md` §5-9）。

## 2. 逐步规范

### KSP-01 立项定档（1-2 分钟）
- 动作：一句话理解需求 → 三问（做什么片/给谁看/多久要）→ **通道判定（走 A／走 B／混合）** → 定档拍板卡：
  `M档标准(Recommended) / L档旗舰 / S档轻量`（`templates/user-gate.md #1`）
- 产出：项目 slug（`YYYYMMDD-主题`）+ `runs/<slug>/STATE.md`（KSP=01）+ **`brief.md` 首行写死「通道＝A／B／A+B」＋「音乐驱动段＝无／C∩A／C∩B（并标 C 段时间码范围）」**（硬规则 #43/#44②）

#### 通道判定卡（KSP-01 必拍板 · 硬规则 #42④）

> **立项第一步 ＝ 判型**。**通道是项目属性，不是档位**（与 S/M/L 无关，承硬规则 #35）——**同一张定档卡上判死**，写进 `brief.md`。**判错通道＝走错整条链路**（A 项目被加剧集前置 = 空转三轮；B 项目被当单集跑 = 首集完成即断线）。**判型要判两次：先判纵向（A／B），再判横向（有没有音乐驱动段 C）**。

**拍板卡（选项卡·推荐项置顶）**：

| 选项 | 含义 | 触发信号 | 走的链路 |
|---|---|---|---|
| **通道 A · 广告/科普/科研视频（Recommended·默认）** | 单支片／多版本单支片（TVC、申报片、招生片、产品片、科普片、科研报告视频） | 单支成片目标；**多平台/多时长版本**（15s/30s/竖版/横版）**≠ 剧集** | **KSP-01 → 07 原链路**（**不加剧集前置**） |
| **通道 B · 剧集/叙事** | 多集／连续／番剧／系列片（**含"先做一集看看"的试播**） | 有**分集**概念：集序、集尾钩子、跨集同一角色/场景 | **KSP-E1~E5 前置 ＋ KSP-02~07 每集循环** |
| **混合 A+B · 双通道并用** | 主体走 B，衍生单支片走 A（或广告线系列化挂 B） | 如"剧集 + 剧集宣传片/先导预告"、"同一 IP 多支广告按季规划" | **主通道链路为准；副通道产物只引主通道事实源**（混用**须走 KSP-C 记录**，硬规则 #42②） |
| 自定义／我来补充 | 上述不覆盖的情况 | — | 制片人据答复判定并留痕 |

**判定口诀（判定顺序不可颠倒）**：
1. **有"分集"才算 B**——有集序/集尾钩子/跨集同一角色场景＝**B**；**多版本单支片、系列化广告（无集序）＝仍走 A**。
2. **剧集即使只先做 EP01，也必须有全季大纲**（走完整 KSP-E1/E2）——**"先做一集看看"不豁免**。
3. **判不出来就默认 A**（通道 A 是安全默认：不加剧集前置，随时可经 **KSP-C** 转 B）。
4. **A→B 或 A/B 混用：一律出 KSP-C 变更决策卡**（改什么／影响哪些关卡／回退范围），**禁止静默切换通道**（硬规则 #42②）。
5. **第二遍判横向（通道 C）——"本片／本段是否音乐驱动"**（硬规则 #43/#44）：判据＝**问"这一段的每一刀为什么在这里切？"**——答"**因为歌到这里是重音**"＝**音乐驱动（C）**；答"因为要传递这条信息"＝**A**；答"因为人物在这里做了这个决定"＝**B**。**是 → 判 C∩A 或 C∩B（并标出哪几段属 C 段·时间码范围）**；**否 → 不进 C**。

#### 横向判定卡：是否音乐驱动（通道 C · KSP-01 同卡拍板 · 硬规则 #43/#44）

> **通道 C ＝ 音乐驱动的横向能力**——**不新开纵向链路**，而是**与 A、B 相交**（硬规则 #44①）。**判定问句与"判型两次"见上「判定口诀」第 5 条**。

| 选项 | 含义 | 触发信号 | 走什么 |
|---|---|---|---|
| **C ∩ A（广告侧）** | 品牌／产品音乐片、主题曲 MV、活动 MV、音乐营销片 | **品牌叙事靠歌承载**（不是靠口播文案）；有品牌 VI／产品数据约束 | `playbooks/mv-production.md` **＋ 通道 A 的 KSP-01~07**（**＋广告法合规 `scripts/ad_forbidden_words.py`／品牌 VI**） |
| **C ∩ B（剧集侧）** | **OP/ED**、插入歌、角色曲 PV、预告 MV | 剧集项目里**以歌定节奏**的段（片头／片尾／插曲位） | `playbooks/op-ed-mv.md` **＋ 挂 KSP-E2 风格圣经 ＋ KSP-E1 时长预算**（**不新增关卡**） |
| **纯 C** | 独立单曲 MV | 无 A 的品牌约束、无 B 的剧情约束 | `playbooks/mv-production.md`（自成一体的视觉概念） |
| **无音乐驱动段（Recommended·默认）** | 全片按文案（A）或戏剧动作（B）驱动 | 无歌／歌只是背景配乐（**背景 BGM ≠ 音乐驱动**） | 按纵向判型链路走；**不引入 C 规则** |
| 自定义／我来补充 | 上述不覆盖 | — | 制片人据答复判定并留痕 |

**C 段的三条硬纪律**（硬规则 #44②）：
1. **组合项目须在 `brief.md` 写明是 C∩A 还是 C∩B，并标出哪几段属 C 段（时间码范围）**——**不写＝判型未完成**。
2. **C 段内无对白／无口播**（人声只属于歌）；**C 段主产物＝卡点表**（`templates/mv-beat-sheet.md`），**不得为 C 段编"四场脊椎／剧透结构"**（硬规则 #43）。
3. **C 规则不得外溢**——**卡点／文字白名单／无对白只对 C 段生效**；**不得要求 A 的口播片按卡点排刀，也不得要求 B 的正片删旁白／按卡点排刀**（硬规则 #44②）。

- **通道 B 的"判型承诺"要落到产物**：**一旦判为 B，KSP-E1 必须产出 `runs/<季slug>/series-config.json`**（承硬规则 #35/#40；`scripts/check_all.py` 与 `scripts/check_series_consistency.py` 按**磁盘形态**识别剧集项目——**有 `series-config.json` 或有 `EPnn/` 集目录＝剧集，自动跑 KSP-E4；否则跳过**）。**故"判了 B 却不落 E1 配置"＝跨集闸被静默跳过**（机器层不会被触发）——**这是判型纪律问题、不是脚本 bug**：**E1 未拍板/未产配置前不得开工单集**（承 #35）。
- **两通道可混用（判型时一并问清）**：
  - **剧集衍生的宣传片／先导预告 → 走 A**：**引剧集《风格圣经》即可，不另做全季大纲**；**单支片不因"源自剧集"而自动获得剧集属性**（不触发跨集一致性闸）。
  - **广告线系列化**（同一 IP 多支、按季规划）→ **挂 B 的《风格圣经》＋跨集资产复用**，但**交期/排播仍按通道 A 的多版本口径**。
- **两通道共用底层（不因通道而分叉）**：知识图谱（`packs/kesheng-kg/`）／**素材入库即标签**（硬规则 #41·混用时也只有**一份** `assets_index.json`）／机器门控（`scripts/check_all.py`）／质量门（`protocols/quality-gate.md`）／红队／检察官（`agents/inspector.md`）／**文学闸（按需启用·仅动画类）**。
- **通道 A 保留资产不得降级**（硬规则 #42③）：brief/概念/口播/分镜/prompt/图表层/**广告法合规**（`scripts/ad_forbidden_words.py`）/**产品公式**（`templates/product-prompt-formula.md`）/**TVC 模板**（`knowledge/tvc-ad-templates.md`）／品牌 VI／科学报告＋PPT／**专业后期与剪辑团队·真人实拍·产品摄影**——**均为保留资产**，**剧集规则不得覆盖或判其违规**；**通道 B 的 #33/#35–#40 不外溢到 A**（逐条限定语见 `docs/DUAL-CHANNEL-AUDIT.md`）。

### KSP-02 需求简报+预注册（必备关卡·最重视）
- 动作：`templates/brief.md` 逐项调研（已提供则跳过）→ 并行 4 约束清单（科学/导演/摄影/受众）→ **预注册标准 3-5 条** → 一次性拍板卡组合（受众/平台/时长/风格/画风/素材缺口，`user-gate.md #2-7`）
- 铁则：**信息缺口必须问清，不许猜**；素材清单（客户资料/官方图/实测数据）列成待办，缺素材走 #7 拍板
- 产出：`brief.md`（含预注册标准+定档+素材状态表）→ 用户确认 ✅

### KSP-03 科学理解（知识关 · 调研报告先读后谈）
> **铁序（本关核心）**：按 `playbooks/science-report-flow.md` 七步执行——调研完成 → **① 报告全文作为中间交付件交给用户（进对话+docx/PPT）** → **工作流硬性停顿** → **② 用户读完 → 明确回复「继续」**（期间可讨论/提意见/问问题/纠正，记 `m2-纪要.md`）→ **③ 收到「继续」后才允许进入任何后续环节与拍板选项**（方案/风格/九宫格/口播稿等一律后置）。**未收到用户「继续」，制片人与任何角色禁止推进下一步/抛拍板选项。**
- 动作：科学顾问 7 步理解法（≥L2）＋受众/导演并行调研 → 事实争议逐个处置（查证/标待确认/升级 #8）；**报告=完整写进对话 + `scientist-报告.docx` + `scientist-讲解.pptx`**（讲透 重点/时间/产品原理/产品卖点/科学原理；docx 用 report-writer/markdown-exporter、PPT 用 ppt-master/markdown-exporter/pipitmk 赋能——见 ORCHESTRATION §5-18）
- **调研图料三件套（本关必做）**：
  1. **科学道理**：原理/公式/因果链/示意图 → 梳理进理解报告与图谱（科学域）
  2. **网图**：公开示意图/结构图/对比图/应用场景图 → 检索建库 `runs/<slug>/refs/`（**每张标注来源+版权状态**；无授权只作参考——构图/结构理解/演示，**绝不入镜**）
  3. **素材图**：客户资料全量收集（官方渲染/实拍/结构图/PDF-PPT抠图）→ 按 `templates/assets-inventory.md` 分类（用途分级×内容类型）+命名（文件名=条目ID）+建台账；**智能入库三件套（每张必做）**：`read_image` 多模态拆解（物品/任务/场景/结构/质感/数据/品牌/实拍）+ 反推AI合成提示词（文字检索键）+ 质量分（★1-5，合规一票否决）——选图/做图按 文字标签+高分 优先（`scripts/annotate_assets.py`）
- **图库使用纪律**：分镜/参考包/九宫格/首帧**必须先从图库挑**（逐镜问"图库里有没有能用的"）；参考包组图=图库资产；不凭空 AI 生成替代有素材的镜头
- **"两点讲明白"（本关必做，给用户看）**——按对象类型：
  - **产品** → ①产品介绍（是什么/解决什么问题）②**产品卖点**（关键参数/对比基准/证据）
  - **科研机构** → ①**研究什么**（方向/领域/解决的问题）②**人员组成**（团队结构/角色/代表作）
  - **设施** → ①**设施能力**（能做什么/指标）②**设施为了什么存在**（科学目标/服务对象）
  - **科普** → **先把人讲明白**（人物/谁在研究/给人看的故事，人的维度先于知识）
- **阅读讨论环节（开放对话，不是选项）**：报告全文展示 → 用户阅读（可打断提问/纠偏/补充材料）→ 讨论要点记录进 `m2-纪要.md` → 用户确认讨论完毕
- 门控：L2 达标 + "待确认"全有去向 + **报告已阅读讨论完毕** + 两点讲清获用户认可 → 才进入 KSP-03.5

### KSP-03.5 主题共识+内容重点对齐（方案前必过）
> **铁序**：出方案（KSP-04）之前，先和用户一起：**① 说清"视频主体"（这条片子讲什么/为谁讲）→ ② 讨论内容重点 → ③ 按用户侧重点加强 → ④ 落成内容重点协议 → 才允许出方案。**
1. **主体共识卡**：制片人/导演用一句话讲清视频主体（产品=介绍+卖点；机构=研究什么+谁在做；设施=能力+为什么存在；科普=讲谁的故事+讲清什么）+ 定位一句话 → 用户确认/纠偏
2. **内容重点清单**：从调研报告+受众模型提炼 **3-8 条候选重点**（每条=信息点+支持证据+对应镜头可能）→ 与用户逐条讨论（用户侧重的加强、不关心的弱化、错的删除）
3. **重点圈选**：用选项卡**多选**（#17）：用户点选侧重条目；讨论排序（P0/P1/弱化/删除）
4. **内容重点协议**：`brief.md` 增补"内容重点协议"（重点×权重×证据×镜头预算分配），后续口播/分镜/时间轴按权重分配时长与镜头数
- 门控：**主体共识+重点协议获用户确认** → 才进入 KSP-04 方案对抗<br>*（方案=执行层；重点是内容层——先定"讲什么重点"，再谈"怎么拍"。）*

### KSP-04 创意概念先行（Insight→Ideation→Evaluation→Presentation→Refine）
> **流程纠正（行业标准，参考 creative-director-skill 的 agency 流程）**：不该"多角色盲出完整方案再评审"——方案互相打架且执行细节前置。正确顺序：
> 1. **Insight（洞察）**：已在前置完成（KSP-03.5 重点协议=洞察+受众证据模型）
> 2. **Ideation（概念生成）**：导演/编剧/摄影指导基于重点协议各出 **5 个创意概念**（不是完整方案！）——方法论：SIT/SCAMPER/TRIZ/Bisociation/换位/加减法/极端化；每概念=**大创意一句话 + 核心信息 + 风格基调(moodboard) + 为什么成立（对接重点协议/受众/证据）+ 概念标题**
> 3. **Evaluation（评分）**：四大维打分（预注册标准/传播力/科学准确/可执行，0-1）＋红队每概念 1-2 条挑战 → 排序
> 4. **Presentation（概念拍板）**：概念卡并列展示（证据先行）→ **选项卡选一/融合/自定义（#9）**
> 5. **Refine（深化）**：**只深化所选概念** → 完整方案（定位/受众/**口播稿(定稿)**/分镜概览/执行计划；导演整合，各角色补位）——**口播稿在方案里就定下来**，不再出现 N 份完整方案互相打架
> 6. 之后：**口播稿（KSP-05，先定内容）**，口播定稿后再做**九宫格风格预览（KSP-04.5，定风格）**——**顺序铁则：口播 → 九宫格 → 分镜**（先讲什么，再定什么风格，才做分镜）。
- 门控：概念拍板 #9 通过 + 深化方案获批 → 用户确认 ✅

### KSP-05 口播稿（先定内容 · KSP-04 深化后的独立拍板点）
> **与 KSP-06 的关系**：**口播稿（本关）→ 分镜/声音/prompt/剪辑（KSP-06 的关内执行步）**；**口播稿未定稿不得做九宫格（KSP-04.5）与分镜**。
- **顺序强制**：**口播多方案竞稿 → 用户选定方案（拍板卡 #16，证据先行：全部方案全文展示）** → 定稿口播稿 → **九宫格风格预览（KSP-04.5，口播定后）** → 分镜 ‖ 声音 → 摄影方案 → prompt 分段并行 ‖ 剪辑预计划 → 美术 VI 复核 → 科学复核 → **红队前置闸**
- **多方案规矩（硬性）**：编剧必须产出 **2-3 个口播方案**（不同方向：建议 = ①直白规格型 ②价值翻译型 ③混合型；或按项目换钩子/结构变体），每个方案 = 全文旁白 + 类型/公式链/语速说明 + 一句话差异点；制片人用选项卡让用户**选一/混搭**（#16）
- 动作：口播稿 v2 先给用户看稿（**多方案一起给**）；**口播稿确认后**才跑分镜表（分镜按稿切段对齐）
- 用户交互：口播方案选择（必拍板）+ 素材缺口/事实争议/风格漂移时；其余结果通知
- 门控：**口播方案已选定+定稿** → 用户确认 ✅（下游 prompt 表另在 KSP-06 过 `scripts/check_prompt_sheet.py` 校验）

### KSP-04.5 九宫格风格预览（风格基线关 · **放在口播之后**）
> **顺序**：口播稿（KSP-05）先定内容 → 本关才做九宫格定风格（口播讲什么，风格就贴合什么）。
- 动作：分镜师用宫格技法（`playbooks/storyboard-grid.md`：Image2 生图九宫格）一次出全片**风格预览九宫格**（构图/配色/材质/光效/画风各格对标方案），美术指导批复风格口径
- 拍板卡：#15 九宫格风格预览（按此风格基线执行 Recommended / 换风格方向重出 / 微调某几格）
- **基线固化（硬规则）**：九宫格确认后，风格 token 块/色板/画风/构图倾向写入分镜表表头；**后续所有分镜与出图必须尊重该基线**——严禁另起风格，防止后续出图"同质化"（AI 通用质感）

### KSP-06 制作交付+出口闸（关内含执行步 ＋ 验收关 · AI 原生两档）
> **关内顺序**：分镜/声音 → 摄影方案 → prompt 分段 ‖ 剪辑预计划 → 美术 VI 复核 → 科学复核 → **红队前置闸** → 陪跑出片 → 出口闸 → 用户签收。
- 执行步门控：prompt 表通过 `scripts/check_prompt_sheet.py` 校验（核心字段完整/口播单独成字段且与口播稿一致/风格token一致/参考@/负面非空 + 图文对位提示；**兼容 `**字段**：` 与 `【字段】` 两代格式**）+ 前置闸 pass + M4 出口清单全勾 → 才进陪跑出片
- 动作：制片人按 `playbooks/production-workflow.md` 陪跑出片（**用户=AI 创作用户，只操作 AI 平台+剪映一键**）→ 导演定剪 → 红队出口闸（评分单+三态）→ **物料多检查**
- **零意外条款（铁则）**：方案/方案包一经交付，**用户绝不允许再准备任何额外素材**——所有需要的图要么①已在素材包内（已下载+来源标注）②附**文生图/图生视频生成 prompt**（用户一键可生成）③来自客户已收集素材。**"拿到交付件后还需拍照/找物/补素材"=流程事故（L1 FAIL）**；出包时逐镜自问"这镜所有素材用户手里都有了吗"。
- **多检查体系（Atelier 检察官模式——每层一个独立上下文检察官，co-scientist 风格：只看证据、不听辩护、不互相复用结论）**——交付前逐层由检察官出报告：
  - **L1 素材检察官**（agent：跑 `check_asset_pack.py` + 逐镜核对 @引用全登记、无"待补充/拍照"提示）
  - **L2 prompt 检察官**（agent：跑 `check_prompt_sheet.py`（核心字段/口播单独且与口播稿一致/风格token一致/参考@/负面非空 ＋ R12 图文对位提示）→ 逐文件细读 + **图文对位硬查**：每镜头播内容 ↔ 参考图/画面必须对位，口播讲 A 参考图不得是 B）
  - **L3 事实检察官**（独立上下文复核：数据出处清单 + 待确认为零/有去向）
  - **L4 出口检察官**（七维评分单 + PASS/CONDITIONAL/BLOCK 三态）
  - **L4.5 总检察官**（汇总 L1-L4 → **检查裁决书**：各层评分+打回清单+三态裁决）
  - **L5 用户签收**（上手包 + 裁决书 + 全部工艺文件，缺一不可）
  - 检察官卡：`agents/inspector.md`（独立上下文、每条结论引证据、给推翻条件、**抽查即全查**、发现问题打回对应角色不代修）
- **交付两档（默认第一档）**：
  - **A 档·多平台上手包（默认）**：科生交付"多平台上手素材包"——每镜【平台对照 prompt（Seedance 2.5/即梦/可灵/LibTV 各一份）+ 参考图包 + 口播 + 抽卡建议 + 画布操作步骤】；**配音=AI 原生（TTS/剪映智能配音/克隆音色，口播稿带读法批注：数字读法/单位不念/型号逐字母/停连重音）——用户零找人零配音**；**用户自己在选定的平台画布/节点上操作生成**；剪映 10 分钟一键后期是可选加分项；**不期待任何专业后期**
  - **B 档·专业增强（可选）**：用户主动要求时，另附"专业交接单"交由第三方（不做是常态）
- 拍板卡：#11 CONDITIONAL（修改后重交付 Recommended）/ #12 BLOCK（打回 Recommended）/ #14 时长预算超限
- 门控：出口闸 PASS（或 CONDITIONAL 循环≤2 后满足）+ **用户签收**（A 档成品+全部工艺文件）

## 2.5 剧集通道（KSP-E）· 剧集项目专用

> **适用判定（KSP-01 就要判死）**：项目是不是**剧集**（多集/连续/番剧/系列片，含"先做一集看看"的试播），**在 KSP-01 立项时判定并写进 `brief.md`**；**剧集是项目属性、不是档位**——与 S/M/L 档无关（L 档单集片不走本通道）；**剧集即使只先做 EP01，也必须走完整 KSP-E1/E2**。
> **铁序**：**E1 全季立项 → E2 风格圣经 → E3 逐集循环 → E4 跨集一致性闸 → E5 发布节奏与追更**；**E1/E2 未获用户拍板前，禁止开工任何单集**（硬规则 #35/#36）。剧集必读：`playbooks/series-production.md`。

### KSP-E4 跨集一致性闸（每集交付前必过·独立上下文）
- 动作：**每集交付前**由**独立上下文**（未参与该集创作者，`subagent`/检察官链路，只看证据不听辩护）执行**跨集一致性检查**，六维：**人物**（脸形/发型/身形/服装 ↔ 圣经锚图）／**色板**（色彩语义/专属色配额/禁串场）／**字形**（片名字/回目/字帖 ↔ 字帖体系）／**母题**（视/听/转场母题按圣经使用，无未登记新增）／**音效**（音色/混音基线/母题音乐用法）／**时长结构**（OP/正片/ED 与该集规范一致）
- 三态：**通过 / 有条件通过（集内回炉 ≤2 循环）/ 打回**；记录落 `runs/<slug>/EPnn/ep-consistency-check.md`（判据｜实际｜比对基准〔圣经版本/锚图文件〕｜结论）
- 与出口闸**并列不可互替**：出口闸查"这一集好不好"，本闸查"这一集与别的集是不是同一部片子"

1. **主通道定链路**：主体走 B（剧集）时，**E1/E2 前置照走**；衍生的单支宣传片/先导预告**单独作为通道 A 项目跑 KSP-01~07**（**引剧集《风格圣经》，不另做全季大纲**，不走 E4）。

5. **与通道 C 组合时（C∩A／C∩B）**：**C 不改变主通道**——主通道链路照走，**只在 `brief.md` 登记交集与 C 段时间码范围**，**C 段按 `playbooks/mv-production.md` 执行**；**C 规则（卡点／文字白名单／无对白）不外溢到 A 的口播片与 B 的正片**（硬规则 #44②）；**C∩B 的 OP/ED 属固定资产**，挂 **KSP-E2＋KSP-E1** 之下、**不新增关卡**。
