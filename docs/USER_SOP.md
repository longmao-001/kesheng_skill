# 科生 · 用户使用流程规范（User SOP · KSP-01~07）

> 版本 v1.0（2026-09）。**用户使用科生时的唯一规范流程**。制片人（主 agent）必须按本流程机械执行：步骤顺序、门控判定、拍板卡交互均不得跳步；例外见 §8 降级通道。
> 配套：`docs/ROLE_WORKFLOWS.md`（角色 SOP）、`orchestration/ORCHESTRATION.md`（派活清单）、`templates/user-gate.md`（拍板卡速查）、`protocols/quality-gate.md`（出口标准）。

## 0. 三条铁则

1. **用户是甲方**：每关结束必须经用户拍板（选项卡）才能推进；未经拍板不得进入下一阶段。
2. **拍板必须选项卡**：一律 `ask_user_question`，≥2 选项、推荐置顶"(Recommended)"、可多选、必留"自定义"（`templates/user-gate.md`）。
3. **证据先行**：基于项目文件的拍板，**先展示文件内容再给选项**（文本贴全文/要点，图片给路径+描述+贴图，数据给来源）；用户看不到依据=盲选，禁止。
4. **知识只进图谱**：任何调研/验证知识 → 域片段 → 重建图谱，不新建概念卡（`orchestration/ORCHESTRATION.md` §5-9）。

## 1. 流程总览（KSP 状态机）

| 步骤 | 名称 | 执行者 | 用户角色 | 通过标准（Gate） | 用户拿到的 |
|---|---|---|---|---|---|

| **KSP-02** | 需求简报+预注册 | 制片人+观众代言人等 | **答题+拍板** | 简报卡定稿（含预注册标准+素材清单） | `brief.md` 确认版 |

## 2. 逐步规范

### KSP-01 立项定档（1-2 分钟）
- 动作：一句话理解需求 → 三问（做什么片/给谁看/多久要）→ 定档拍板卡：
  `M档标准(Recommended) / L档旗舰 / S档轻量`（`templates/user-gate.md #1`）
- 产出：项目 slug（`YYYYMMDD-主题`）+ `runs/<slug>/STATE.md`（KSP=01）

### KSP-02 需求简报+预注册（必备关卡·最重视）
- 动作：`templates/brief.md` 逐项调研（已提供则跳过）→ 并行 4 约束清单（科学/导演/摄影/受众）→ **预注册标准 3-5 条** → 一次性拍板卡组合（受众/平台/时长/风格/画风/素材缺口，`user-gate.md #2-7`）
- 铁则：**信息缺口必须问清，不许猜**；素材清单（客户资料/官方图/实测数据）列成待办，缺素材走 #7 拍板
- 产出：`brief.md`（含预注册标准+定档+素材状态表）→ 用户确认 ✅

### KSP-03 科学理解（知识关 · 调研报告先读后谈）
> **铁序（本关核心）**：按 `playbooks/science-report-flow.md` 七步执行——调研完成 → **① 报告全文作为中间交付件交给用户（进对话+docx/PPT）** → **工作流硬性停顿** → **② 用户读完 → 明确回复「继续」**（期间可讨论/提意见/问问题/纠正，记 `m2-纪要.md`）→ **③ 收到「继续」后才允许进入任何后续环节与拍板选项**（方案/风格/九宫格/口播稿等一律后置）。**未收到用户「继续」，制片人与任何角色禁止推进下一步/抛拍板选项。**
- 动作：科学顾问 7 步理解法（≥L2）＋受众/导演并行调研 → 事实争议逐个处置（查证/标待确认/升级 #8）；**报告=完整写进对话 + `scientist-报告.docx` + `scientist-讲解.pptx`**（讲透 重点/时间/产品原理/产品卖点/科学原理；docx 用 report-writer/markdown-exporter、PPT 用 ppt-master/markdown-exporter/pipitmk 赋能——见 ORCHESTRATION §5-18）
- **调研图料三件套（本关必做）**：
  1. **科学道理**：原理/公式/因果链/示意图 → 梳理进理解报告与图谱（科学域）
  2. **网图**：公开示意图/结构图/对比图/应用场景图 → 检索建库 `runs/<slug>/refs/`（**每张标注来源+版权状态**；无授权只作参考——构图/结构理解/演示，**绝不入镜**）
  3. **素材图**：客户资料全量收集（官方渲染/实拍/结构图/PDF-PPT抠图）→ 按 `templates/assets-inventory.md` 分类（用途分级×内容类型）+命名（文件名=条目ID）+建台账 `assets-inventory.md`（含来源·授权）
- **图库使用纪律**：分镜/参考包/九宫格/首帧**必须先从图库挑**（逐镜问"图库里有没有能用的"）；参考包组图=图库资产；不凭空 AI 生成替代有素材的镜头
- **"两点讲明白"（本关必做，给用户看）**——按对象类型：
  - **产品** → ①产品介绍（是什么/解决什么问题）②**产品卖点**（关键参数/对比基准/证据）
  - **科研机构** → ①**研究什么**（方向/领域/解决的问题）②**人员组成**（团队结构/角色/代表作）
  - **设施** → ①**设施能力**（能做什么/指标）②**设施为了什么存在**（科学目标/服务对象）
  - **科普** → **先把人讲明白**（人物/谁在研究/给人看的故事，人的维度先于知识）
- **阅读讨论环节（开放对话，不是选项）**：报告全文展示 → 用户阅读（可打断提问/纠偏/补充材料）→ 讨论要点记录进 `m2-纪要.md` → 用户确认讨论完毕
- 门控：L2 达标 + "待确认"全有去向 + **报告已阅读讨论完毕** + 两点讲清获用户认可 → 才进入 KSP-03.5

### KSP-03.5 主题共识+内容重点对齐（方案前必过）
> **铁序**：出方案（KSP-04）之前，先和用户一起：**① 说清"视频主体"（这条片子讲什么/为谁讲）→ ② 讨论内容重点 → ③ 按用户侧重点加强 → ④ 落成内容重点协议 → 才允许出方案。**
1. **主体共识卡**：制片人/导演用一句话讲清视频主体（产品=介绍+卖点；机构=研究什么+谁在做；设施=能力+为什么存在；科普=讲谁的故事+讲清什么）+ 定位一句话 → 用户确认/纠偏
2. **内容重点清单**：从调研报告+受众模型提炼 **3-8 条候选重点**（每条=信息点+支持证据+对应镜头可能）→ 与用户逐条讨论（用户侧重的加强、不关心的弱化、错的删除）
3. **重点圈选**：用选项卡**多选**（#17）：用户点选侧重条目；讨论排序（P0/P1/弱化/删除）
4. **内容重点协议**：`brief.md` 增补"内容重点协议"（重点×权重×证据×镜头预算分配），后续口播/分镜/时间轴按权重分配时长与镜头数
- 门控：**主体共识+重点协议获用户确认** → 才进入 KSP-04 方案对抗<br>*（方案=执行层；重点是内容层——先定"讲什么重点"，再谈"怎么拍"。）*

### KSP-04 创意概念先行（Insight→Ideation→Evaluation→Presentation→Refine）
> **流程纠正（行业标准，参考 creative-director-skill 的 agency 流程）**：不该"多角色盲出完整方案再评审"——方案互相打架且执行细节前置。正确顺序：
> 1. **Insight（洞察）**：已在前置完成（KSP-03.5 重点协议=洞察+受众证据模型）
> 2. **Ideation（概念生成）**：导演/编剧/摄影指导基于重点协议各出 **5 个创意概念**（不是完整方案！）——方法论：SIT/SCAMPER/TRIZ/Bisociation/换位/加减法/极端化；每概念=**大创意一句话 + 核心信息 + 风格基调(moodboard) + 为什么成立（对接重点协议/受众/证据）+ 概念标题**
> 3. **Evaluation（评分）**：四大维打分（预注册标准/传播力/科学准确/可执行，0-1）＋红队每概念 1-2 条挑战 → 排序
> 4. **Presentation（概念拍板）**：概念卡并列展示（证据先行）→ **选项卡选一/融合/自定义（#9）**
> 5. **Refine（深化）**：**只深化所选概念** → 完整方案（定位/文案结构/分镜概览/执行计划；导演整合，各角色补位）——**不再出现 N 份完整方案互相打架**
> 6. 之后：九宫格风格预览（04.5）
- 门控：概念拍板 #9 通过 + 深化方案获批 → 用户确认 ✅

### KSP-04.5 九宫格风格预览（风格基线关）
- 动作：分镜师用宫格技法（`playbooks/storyboard-grid.md`：Image2 生图九宫格）一次出全片**风格预览九宫格**（构图/配色/材质/光效/画风各格对标方案），美术指导批复风格口径
- 拍板卡：#15 九宫格风格预览（按此风格基线执行 Recommended / 换风格方向重出 / 微调某几格）
- **基线固化（硬规则）**：九宫格确认后，风格 token 块/色板/画风/构图倾向写入分镜表表头；**后续所有分镜与出图必须尊重该基线**——严禁另起风格，防止后续出图"同质化"（AI 通用质感）

### KSP-05 口播稿→分镜/声音/prompt/剪辑（执行关）
- **顺序强制**：**口播多方案竞稿 → 用户选定方案（拍板卡 #16，证据先行：全部方案全文展示）** → 定稿口播稿 → 分镜 ‖ 声音 → 摄影方案 → prompt 分段并行 ‖ 剪辑预计划 → 美术 VI 复核 → 科学复核 → **红队前置闸**
- **多方案规矩（硬性）**：编剧必须产出 **2-3 个口播方案**（不同方向：建议 = ①直白规格型 ②价值翻译型 ③混合型；或按项目换钩子/结构变体），每个方案 = 全文旁白 + 类型/公式链/语速说明 + 一句话差异点；制片人用选项卡让用户**选一/混搭**（#16）
- 动作：口播稿 v2 先给用户看稿（**多方案一起给**）；**口播稿确认后**才跑分镜表（分镜按稿切段对齐）
- 用户交互：口播方案选择（必拍板）+ 素材缺口/事实争议/风格漂移时；其余结果通知
- 门控：**口播方案已选定+定稿** + prompt 表通过 `scripts/check_prompt_sheet.py` 校验（R1-R11，含口播单独字段）+ 前置闸 pass + M4 出口清单全勾 → 用户确认 ✅

### KSP-06 制作交付+出口闸（验收关 · AI 原生两档）
- 动作：制片人按 `playbooks/production-workflow.md` 陪跑出片（**用户=AI 创作用户，只操作 AI 平台+剪映一键**）→ 导演定剪 → 红队出口闸（评分单+三态）→ **物料多检查**
- **零意外条款（铁则）**：方案/方案包一经交付，**用户绝不允许再准备任何额外素材**——所有需要的图要么①已在素材包内（已下载+来源标注）②附**文生图/图生视频生成 prompt**（用户一键可生成）③来自客户已收集素材。**"拿到交付件后还需拍照/找物/补素材"=流程事故（L1 FAIL）**；出包时逐镜自问"这镜所有素材用户手里都有了吗"。
- **多检查体系（Atelier 检察官模式——每层一个独立上下文检察官，co-scientist 风格：只看证据、不听辩护、不互相复用结论）**——交付前逐层由检察官出报告：
  - **L1 素材检察官**（agent：跑 `check_asset_pack.py` + 逐镜核对 @引用全登记、无"待补充/拍照"提示）
  - **L2 prompt 检察官**（agent：跑 `check_prompt_sheet.py`（R1-R11 + R12 图文对位提示）→ 逐文件细读 + **图文对位硬查**：每镜头播内容 ↔ 参考图/画面必须对位，口播讲 A 参考图不得是 B）
  - **L3 事实检察官**（独立上下文复核：数据出处清单 + 待确认为零/有去向）
  - **L4 出口检察官**（七维评分单 + PASS/CONDITIONAL/BLOCK 三态）
  - **L4.5 总检察官**（汇总 L1-L4 → **检查裁决书**：各层评分+打回清单+三态裁决）
  - **L5 用户签收**（上手包 + 裁决书 + 全部工艺文件，缺一不可）
  - 检察官卡：`agents/inspector.md`（独立上下文、每条结论引证据、给推翻条件、**抽查即全查**、发现问题打回对应角色不代修）
- **交付两档（默认第一档）**：
  - **A 档·多平台上手包（默认）**：科生交付"多平台上手素材包"——每镜【平台对照 prompt（Seedance 2.5/即梦/可灵/LibTV 各一份）+ 参考图包 + 口播 + 抽卡建议 + 画布操作步骤】；**配音=AI 原生（TTS/剪映智能配音/克隆音色，口播稿带读法批注：数字读法/单位不念/型号逐字母/停连重音）——用户零找人零配音**；**用户自己在选定的平台画布/节点上操作生成**；剪映 10 分钟一键后期是可选加分项；**不期待任何专业后期**
  - **B 档·专业增强（可选）**：用户主动要求时，另附"专业交接单"交由第三方（不做是常态）
- 拍板卡：#11 CONDITIONAL（修改后重交付 Recommended）/ #12 BLOCK（打回 Recommended）/ #14 时长预算超限
- 门控：出口闸 PASS（或 CONDITIONAL 循环≤2 后满足）+ **用户签收**（A 档成品+全部工艺文件）

### KSP-07 知识萃取归档（闭环）
- 动作：通用知识 → 域片段 → `build_union_kg.py` 重建 → **追加失败教训到 `knowledge/FAILURE-LIBRARY.md`**（现象/根因/已固化到哪/证据）→ 交付包归档（成片/分镜表/prompt 表/纪要/来源清单）
- **开工前读库**：KSP-01/02 简报阶段先过一遍失败图书馆，同类问题直接规避（防重复踩坑）
- **runs/ 只放项目**：`runs/` 只允许项目 run（每项目一个 `<slug>/`）；非项目散落/临时（`_tmp-*`/`_lessons`/`_research-*`）一律不进或交付前删；交付前跑 `python scripts/check_runs_clean.py` 守护（见 ORCHESTRATION §5-15）
- 交付包结构：`runs/<slug>/delivery/{成片, storyboard.md, prompts.md, README.md}`
- 隐私：`kb/隐私红线.md` 三分法；项目专有信息零入库

### KSP-C 变更控制（任何时候）
- 触发：用户中途改需求/换平台/加版本
- 动作：变更决策卡（改什么/影响哪些 KSP/重做范围/成本）→ 用户拍板 → 回退到受影响最早的关卡重走 §2 对应步骤 → STATE.md 记录版本（v1/v2…）
