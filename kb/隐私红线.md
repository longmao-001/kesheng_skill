# 隐私红线（知识入库脱敏规则）

> 本 skill 会给专业人士使用并持续升级分发。**一旦项目专有信息混入 kb/，下次把 skill 给别人用时就等于把客户的机密送了出去。** 本文件的优先级高于一切"知识积累"的冲动。

## 三分法（每条候选知识先归类）

### 🟢 可直接入库：公开通用知识
- 教科书级概念、原理、机制（如"CRISPR 是原核生物适应性免疫系统"）
- 已公开发表论文中的**通用**结论与里程碑数据（必须能标注公开出处）
- 公开大事记、公认领域内常识
- 通用类比、通用可视化手法、通用叙事技巧

### 🟡 脱敏后可入库：带项目痕迹的通用知识
从项目里悟到、但裹着项目外衣的东西，**泛化处理**后才能入库：
- 去掉专名：项目代号、产品名、机构名、人名 → "某作物""一类黄酮通路"
- 数值模糊化：未公开的具体数值 → 删掉，或换成公开文献的量级表述
- 路线泛化：客户的具体技术组合 → 抽象成该领域的通用方法学
- 组合去标识：单条都公开、拼起来能猜出项目的 → 拆开或舍弃

### 🔴 禁止入库：项目专有信息
- 未公开的实验数据、结果、阶段性结论
- 产品名称、代号、配方、参数、技术路线细节
- 客户/合作方/团队成员的身份信息
- 申报书内容、时间节点、经费、评审细节
- NDA/保密协议覆盖的一切
- **能反推出"谁在做什么"的任何组合信息**

## 脱敏检查清单（每条笔记入库前逐项过）

- [ ] 无任何未公开数值、名称、代号、技术路线细节
- [ ] 无项目名/机构名/人名/合作方名
- [ ] 组合推断测试：同行看这条笔记，猜不出客户在做什么项目
- [ ] 来源栏写的是公开渠道（论文 DOI/教科书/官方发布），不是"项目调研"
- [ ] frontmatter 已标 `隐私: 公开通用`
- [ ] 有任何一项拿不准 → **不入库**

## 项目文件的物理隔离

- 项目制品（分镜表、prompt 表、客户素材、申报文案）**只存在用户的项目目录**，永不复制进 skill 目录
- kb/ 只收"换一个客户照样成立"的知识
- 会议纪要和理解报告属于项目文件，留在项目目录；其中提炼出的通用概念才进 kb/

## 底线原则

知识库缺一条笔记，下次补就是；机密泄一次，无法收回。**拿不准，就不入库。**
