# 多 Agent 辩论会议协议（Meeting Protocol）v2

> v1 设计依据：Du et al. 多 agent 辩论（arXiv:2305.14325）、MAD（arXiv:2305.19118）、MetaGPT、Anthropic 多 agent 工程实践。
> v2 升级依据（2026-08 大厂调研）：Anthropic《How we built our multi-agent research system》+《Building Effective Agents》、OpenAI Agents SDK/Swarm、Google A2A/ADK、Microsoft Magentic-One/AutoGen、LangChain 多 agent 选型指南。关键结论：**多 agent 的收益在并行与对立审查，成本约 15×；会议和干活要分开；制品落盘只传轻引用；停滞要显式检测。**

## 〇、总纲：会议与干活分开（v2 核心）

- **干活**（调研/写 prompt/做分镜）：subagent 隔离并行，制品直接落盘，会议里只传"路径+三五句摘要+置信度自评"（Anthropic 制品落盘模式，防"电话游戏"）
- **开会**（对抗/裁决）：才切共享上下文的群聊模式，且设显式终止条件（最大轮数硬上限）
- **每次开全会前，制片人必须先回答："这个决策点值不值 15 倍成本？"** 不值就降级为小组会或单干+评审闸

## 一、里程碑分级配置（三档投入，写死）

| 里程碑 | 配置 | 依据 |
|---|---|---|
| **M1 需求简报** | 制片人+观众代言人双人小会；科学顾问/视觉导演各自单干交一页约束清单（并行、不开会） | 简单任务 1-2 agent 档 |
| **M2 科学理解** | **orchestrator-worker 并行调研**：制片人拆 3-5 个独立方向，科学顾问/观众代言人/视觉导演各带 subagent 盲并行，制品落素材库，回传摘要+路径+信源自评 | breadth-first 是多 agent 最大收益场景（Anthropic：性能高 90.2%） |
| **M3 制作方案** | **唯一全开全会**：完整 Phase 0-5 对抗；盲提案限 3 份（编剧/视觉导演/制片人各一） | 高价值多视角决策，唯一值 15× 的点 |
| **M4 分镜+prompt** | **单干+评审闸，不开对抗会**：视觉导演主导，prompt 工程师并行转写（sectioning），红队前置闸逐条过，科学顾问只在涉科学画面镜头被 @ | 强耦合单一创作任务不宜对抗（Anthropic 共识） |
| **M5 制作交付** | **独立收尾审校**：一个未参与前期创作的新上下文 agent，拿 Phase 0 标准和素材库逐项核对，出评分单（0.0-1.0+pass/fail） | Anthropic CitationAgent 模式；新上下文避免既得利益偏差 |

## 二、制片人双账本（Magentic-One 机制）

每个里程碑维护两本账：
- **任务账本**：已确认事实 / 有依据的猜测 / 总体计划
- **进度账本**：每步自查"这步达标了吗"；**连续两轮发言无新论点、无制品改动、无标准更新 → 判定停滞 → 停止辩论，重新分解议题或升级用户**（不做自由心证的继续）

## 三、会议阶段（M3 全会完整流程；小组会裁剪用）

### Phase 0 — 简报确认（主席）
复述需求简报+硬约束；**预注册评审标准** 3-5 条（先于任何方案，防裁决时临时编理由）。

### Phase 1 — 盲独立提案（并行、上下文隔离）
- 提案任务书必须含四要素：**目标、输出格式（固定模板）、可用素材范围、任务边界**（Anthropic 实测：缺了就重复劳动或留缺口）
- 各角色上下文隔离（天然盲审），制品落盘，主席收齐后同时公开
- 宿主支持子 agent 时用并行子 agent 生成（真独立）

### Phase 2 — 辩论第一轮（交叉质询）
固定顺序：编剧→视觉导演→科学顾问→prompt 工程师→观众代言人→**红队最后**。
三段式发言（缺一不可）：①钢炼对手最强论点 ②按 Phase 0 标准反驳或支持 ③给具体制品改动。空泛发言无效，主席要求重写。

### Phase 3 — 辩论第二轮（立场更新）
每人必须声明"我在 X 问题上改变立场，因为 Y"或"我坚持，因为 Z"。
**停止规则**：默认 2 轮；无新论点立即裁决；硬上限 3 轮；触发双账本停滞检测 → 立即停，重新分解或升级。

### Phase 4 — 裁决（主席）
按预注册标准逐条打分。**事实性争议不许折中**——查证或升级用户。

### Phase 5 — 制品交接
制品落盘+轻引用（路径+摘要+置信度）；附下一里程碑交接卡：**谁来、拿什么、验收什么**（A2A Agent Card 思路）。

## 四、红队两道闸（v2 新增，替代"每场必到"）

1. **前置拦截闸**（M4 prompt 送生成前/制品出闸前）：只查硬性违规——科学错误、品牌禁区、平台审核红线、数据无出处。pass/fail+一句话理由，不展开讨论
2. **出口评审闸**（里程碑出口）：按预注册标准打分，不达标打回作者修改，最大循环 2 次（AutoGen 最大消息数思路）
3. **全面对抗只保留在 M3**——红队火力集中在最值钱的决策点

## 五、反"假共识"机制（七条，保留 v1）

1. 盲独立立场先行 2. 指定轮换红队 3. 有原则的针锋相对（反对必须引用预注册标准，禁止每点必杠）4. 异议配额：≥3 条实质异议被提出并解决 5. 提前共识警报：零立场变化→加赛或升级 6. 裁判纪律：只用预注册标准 7. 制品增量才算数

## 六、成本控制硬规则（v2 新增）

- **三档投入**：M1/M5=1-2 角色；M2=3-5 并行 worker；仅 M3 全开
- **模型异构**（宿主支持时）：制片人/红队终审用最强模型；M2 调研、prompt 批量转写用便宜模型
- **确定性流转用规则不用判断**：里程碑顺序、发言顺序、终止条件由制片人按本表机械执行；只有"选哪份方案/是否停滞/是否达标"留给判断
- 量化锚点：全面对抗会 ≈15× 单聊 token，每个里程碑开始前重估一次值不值

## 七、升级给用户（甲方）的情形

- 简报关键信息缺失（受众/平台/时长/用途）——Phase 1 前必问
- 事实/科学性争议内部无法裁决——绝不折中
- 品味、品牌、价值观取舍；有争议的叙事框架
- 停滞检测触发且重分解后仍阻塞
- 范围冲突（如分镜镜头数超出可行制作量）
- **每个里程碑的会议纪要必须交给用户确认后才推进下一阶段**
