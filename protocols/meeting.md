# 多 Agent 会议与协作协议（Meeting & Collaboration Protocol）v3

> v1 设计依据：Du et al. 多 agent 辩论（arXiv:2305.14325）、MAD（arXiv:2305.19118）、MetaGPT、Anthropic 多 agent 工程实践。
> v2 升级依据（2026-08 大厂调研）：Anthropic《How we built our multi-agent research system》+《Building Effective Agents》、OpenAI Agents SDK/Swarm、Google A2A/ADK、Microsoft Magentic-One/AutoGen、LangChain 多 agent 选型指南。关键结论：**多 agent 的收益在并行与对立审查，成本约 15×；会议和干活要分开；制品落盘只传轻引用；停滞要显式检测。**
> v3 升级依据（2026-09）：落地为**本机 DSH 真多 agent 执行**——每角色独立上下文 subagent（`subagent`/`subagent_fork`/`workflow`），黑板轻引用（`templates/handoff.md`）。编排操作见 `orchestration/ORCHESTRATION.md`；选型论证见 `docs/DESIGN.md`。

## 〇、总纲：会议与干活分开

- **干活**（调研/写 prompt/做分镜）：subagent 隔离并行，制品直接落盘黑板，会议里只传"路径+三五句摘要+置信度自评"（Anthropic 制品落盘模式，防"电话游戏"）
- **开会**（对抗/裁决）：制片人读各 📤 统合，只在 M3 开真对抗（交叉质询轮）；其余里程碑=裁决式，不开群聊
- **每次开全会前，制片人必须先回答："这个决策点值不值 15 倍成本？"** 不值就降级为裁决式或单干+评审闸

## 一、里程碑分级配置（三档投入，写死）

| 里程碑 | 配置 | 真 agent 实现 |
|---|---|---|
| **M1 需求简报** | 制片人+观众代言人双人小会；科学顾问/导演/摄影指导各自单干交一页约束清单（并行、不开会） | 并行 4 worker：科学顾问→硬约束清单 / 导演→艺术基调 / 摄影指导→可拍约束清单 / 观众代言人→受众证据模型；制片人汇总 |
| **M2 科学理解** | orchestrator-worker 并行调研：拆 3-5 个独立方向，盲并行，制品落素材库 | `subagent` 并行 3-5 路（`workflow` 可全自动）——breadth-first 是多 agent 最大收益场景 |
| **M3 制作方案** | **唯一全开对抗**：完整 Phase 0-5；盲提案限 4 份（编剧/分镜师/摄影指导/导演） | 盲提案并行 4 路 → 交叉质询并行 4 路（L 档+红队并行）→ 导演整合 v1 → 制片人按预注册标准复核裁决 |
| **M4 分镜+prompt** | 单干+评审闸，不开对抗会：分镜师主导分镜，声音设计师并行出声音方案，摄影指导出摄影方案，prompt 工程师并行转写，剪辑师出剪辑预计划，红队前置闸，科学顾问只被 @ 涉科学镜头 | 编剧→(分镜师‖声音设计师)→摄影指导→prompt 分段并转写+剪辑预计划→美术VI复核→科学顾问复核（`subagent_fork`）→红队前置闸（独立上下文 pass/fail） |
| **M5 制作交付** | 独立收尾审校：未参与前期创作的新上下文 agent，拿 Phase 0 标准和素材库逐项核对，出评分单 | 红队/Reviewer `subagent`：三态裁决（PASS/CONDITIONAL/BLOCK）+ 0.0-1.0 评分单；打回 ≤2 循环 |

## 二、制片人双账本（Magentic-One 机制）

每个里程碑维护两本账：
- **任务账本**：已确认事实 / 有依据的猜测 / 总体计划
- **进度账本**：每步自查"这步达标了吗"；**连续两轮发言无新论点、无制品改动、无标准更新 → 判定停滞 → 停止辩论，重新分解议题或升级用户**（不做自由心证的继续）

## 三、会议阶段（M3 全会完整流程；小组会/裁决式裁剪用）

### Phase 0 — 简报确认（导演/制片人）
复述需求简报+硬约束；**预注册评审标准** 3-5 条（先于任何方案，防裁决时临时编理由）。定档 S/M/L。

### Phase 1 — 盲独立提案（并行、上下文隔离）
- **执行**：并行派生 4 个 `subagent`（编剧/分镜师/摄影指导/导演），prompt 模板见编排手册 §2，**禁止读其他提案文件**（制片人在提示中明确列出"禁读清单"）
- 提案任务书必须含四要素：**目标、输出格式（固定模板）、可用素材范围、任务边界**（Anthropic 实测：缺了就重复劳动或留缺口）
- 制品落盘 `runs/<项目>/proposals/`，制片人收齐后同时公开（轻引用）

### Phase 2 — 交叉质询（并行、上下文隔离）
- **执行**：每个提案 agent 只读**另两份**提案+预注册标准，写一份质询（①最强可采纳点 ②按标准编号的反驳 ③整合建议）→ `runs/<项目>/m3-critiques/`；L 档加红队 1-3 条致命反对（每条：攻击点/依据标准/推翻条件）
- 固定角色顺序仅用于**裁决顺序**（编剧→分镜师→摄影指导→声音设计师→剪辑师→美术指导→科学顾问→prompt 工程师→观众代言人→红队），不再要求同上下文轮流发言

### Phase 3 — 立场更新（制片人汇总判断）
- 每个提案 agent 的质询中必须声明"我在 X 问题上改变立场，因为 Y"或"我坚持，因为 Z"
- **停止规则**：默认 2 轮；无新论点立即裁决；硬上限 3 轮；触发双账本停滞检测 → 立即停，重新分解或升级

### Phase 4 — 裁决（制片人）
按预注册标准逐条打分。**事实性争议不许折中**——查证或升级用户。

### Phase 5 — 制品交接
制品落盘+轻引用（路径+摘要+置信度）；附下一里程碑交接卡：**谁来、拿什么、验收什么**（A2A Agent Card 思路）。

## 四、红队两道闸（无须"每场必到"）

1. **前置拦截闸**（M4 prompt 送生成前/制品出闸前）：独立上下文红队 subagent 只查硬性违规——科学错误、品牌禁区、平台审核红线、数据无出处。pass/fail+一句话理由，不展开讨论
2. **出口评审闸**（M5 里程碑出口）：独立上下文（未参与创作）按预注册标准打分，PASS/CONDITIONAL/BLOCK，不达标打回作者修改，最大循环 2 次（AutoGen 最大消息数思路）
3. **全面对抗只保留在 M3**——红队火力集中在最值钱的决策点

## 五、反"假共识"机制（七条）

1. 盲独立立场先行（并行 subagent，真隔离）
2. 指定轮换红队（独立上下文）
3. 有原则的针锋相对（反对必须引用预注册标准，禁止每点必杠）
4. 异议配额：≥3 条实质异议被提出并解决
5. 提前共识警报：零立场变化→加赛或升级
6. 裁判纪律：只用预注册标准
7. 制品增量才算数（黑板文件有实际改动）

## 六、成本控制硬规则

- **三档投入**：M1/M5=1-3 角色；M2=3-5 并行 worker；仅 M3 全开——S/M/L 档定义见 `docs/DESIGN.md` §4
- **模型异构**（宿主支持时）：制片人/红队终审用最强模型；M2 调研、prompt 批量转写用便宜模型
- **确定性流转用规则不用判断**：里程碑顺序、发言顺序、终止条件由制片人按本表机械执行；只有"选哪份方案/是否停滞/是否达标"留给判断
- 量化锚点：全面对抗会 ≈15× 单聊 token，每个里程碑开始前重估一次值不值

## 七、升级给用户（甲方）的情形

- 简报关键信息缺失（受众/平台/时长/用途）——Phase 1 前必问
- 事实/科学性争议内部无法裁决——绝不折中
- 品味、品牌、价值观取舍；有争议的叙事框架
- 停滞检测触发且重分解后仍阻塞
- 范围冲突（如分镜镜头数超出可行制作量）
- **每个里程碑的会议纪要必须交给用户确认后才推进下一阶段**

**拍板选项卡（硬规则）**：所有升级用户的拍板点用 `ask_user_question` 提交选项卡（≥2 选项、推荐置顶"(Recommended)"、可多选、必留"自定义"兜底），预置选项速查表见 `templates/user-gate.md`；裁决结果（含红队三态）必须转成拍板卡，不能把评审意见原样甩给用户。
