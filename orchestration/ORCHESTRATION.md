# 🎬 科生编排手册（Orchestration Manual）

> 版本 v2.0 (2026-09)。制片人（主 agent）在 DeepSeek Harness (DSH) 里驱动科生团队**真多 agent 协作**的唯一操作手册。
> 编排底座与 Atelier 一致（`f:/AI/atelier/docs/DSH_ORCHESTRATION.md` 的同构版）；设计依据见 `docs/DESIGN.md`。

## 0. 术语与角色定位

- **制片人 = 主 agent（orchestrator）**：唯一"看得见全局"的角色。它**编排**，不亲自写内容（S 档除外）。
- **worker = 被派生的 subagent**：导演 / 编剧 / 分镜师 / 美术指导 / 摄影指导 / 声音设计师 / 剪辑师 / 科学顾问 / prompt 工程师 / 观众代言人 / 红队，各自独立上下文。
- **黑板 = 工坊目录**：`F:/AI/kesheng/runs/<项目slug>/`，所有 agent 的读写介质。项目 slug 用 `YYYYMMDD-主题缩写`（如 `20260901-基因编辑`）。

## 1. 工具映射（角色 → DSH 机制）

| 机制 | 工具 | 用途 | 科生用法 |
|---|---|---|---|
| 派生独立 worker | `subagent`（后台默认 true=并行） | 每个角色独立上下文、真并行 | M2 调研 / M3 概念先行 / M4 转写 |
| 继承上下文复核 | `subagent_fork`（后台默认 true） | 用下游角色视角复核上游制品 | 科学顾问复核 prompt 表；制片人复核争议条款 |
| 全自动扇出 | `workflow`（JS 多阶段+屏障） | 无依赖阶段的真并行、批量转写 | 用户说"全自动跑完"时：`orchestration/kesheng_workflow.js` |
| 人在回路关卡 | `ask_user_question` | 每里程碑停等用户确认 | M1/M3/M5 必用；M2/M4 出口按定档用 |
| 进度可视化 | `todo_write` | 里程碑/派活清单 | 开工即建，完成即更 |
| 制品读写 | `read` / `write` / `edit` / `glob` | 黑板读写 | 制片人汇总；worker 产出 |

## 2. 派活统一 prompt 模板（五段式，粘贴即用）

```
你被指派为「科生」团队的<角色>。你是独立上下文的 subagent——看不到本会话主对话，
只以黑板文件和本提示为事实来源。
开工三步:
  ① 用 read 工具读 F:/AI/kesheng/agents/<角色文件名>.md 作为你的角色卡，遵循其全部指令；
     再用统一知识图谱查你的 domain: python F:/AI/kesheng/packs/kg_query.py --depth 2 --domain <你的域> <任务关键词>
     （结果含实体属性+1跳邻居+权威正文路径；按结果 read 需要的原文，不要一次性全读）
  ② 读黑板: F:/AI/kesheng/runs/<项目slug>/brief.md (项目简报+预注册标准+档位)。
  ③ 读取上游📤: <上游制品文件路径>（若无则略过）。
任务: <一句话任务，含交付格式要求>
上游📤: <上游的"📤"块原文，未公开则写"盲提供案，不提供其他提案内容">
输出要求:
  - 完整产出写入 F:/AI/kesheng/runs/<项目slug>/<角色>-<制品>.md
  - 末尾必须有 `## 📤 传递给下游 (@制片人)` 块（格式见 templates/handoff.md）
  - 分段落盘：长文档每完成一节立即写盘，禁止憋单文件
  - 科学准确铁律：数据有出处；不确定标"待确认"；绝不编造
  - 知识沉淀：调研中新学到的通用知识追加到对应域片段 packs/<域>-kg/kg.json（带 sources），由制片人重建图谱；禁止新建 markdown 概念卡
  - 结尾附 3 行总结: 关键产出 / 置信度自评(高/中/低) / 需要制片人拍板的事
```

## 4. 里程碑派活清单（关卡式默认流程）

### M1 简报 + 约束清单（并行 4 路）
1. 制片人用 `templates/brief.md` 向用户调研 → 定稿 **预注册标准 + 档位(S/M/L)** → 写 `brief.md`。
2. 并行派生 4 个 subagent：
   - 科学顾问 → 一页**科学硬约束清单**（哪些表述必须精确/哪些禁止）
   - 导演 → **艺术基调**（导演阐述雏形：主题一句话/风格关键词/节奏方向）
   - 摄影指导 → 一页**可拍约束清单**（平台能力边界/拍法路线/风格禁区）
   - 观众代言人 → **受众证据模型**（受众消费场景/最先看的指标/证据可视化优先）
3. 制片人汇总进 `brief.md` → `ask_user_question` 请用户确认。

### M2 科学理解（fan-out 3-5 路，档位 L 可扩 5）
| 路 | 角色 | 方向 |
|---|---|---|
| 1 | 科学顾问 | 7 步深度理解法 → `scientist-理解报告.md`（含 L 等级自评+待确认清单）；**完整报告写进对话 + docx + PPT**（§5-18：重点/时间/产品原理/产品卖点/科学原理） |
| 2 | 观众代言人 | 受众语境与证据映射（受众能看懂的数据点/真实素材清单） |
| 3 | 导演 | 艺术基调与可拍性调研（叙事节奏方向/全片气质/镜头语汇候选） |
| 4/5 可选 | 美术指导 / 编剧 | 风格方向调研（色板/VI 联想）/ 叙事角度初探 |

**M2 同步 · 素材智能入库（必做）**：素材库建库（`assets-inventory.md`）时**每张素材做三件套**——①`read_image` **多模态拆解**（物品/任务/场景/结构/质感/数据/品牌/实拍）②**反推 AI 合成提示词**（文字检索键，可复用生成）③**质量分**（★1-5，合规一票否决）；脚手架 `scripts/annotate_assets.py`；后续选图/做图按 **文字标签+高分** 优先（见 `templates/assets-inventory.md`）。**按文件类型的固定提取动作+红线见 `docs/ASSET-TYPES.md`**（视频抽帧/竖屏重构图/勿叠logo；矢量光栅化+官方取色；PPT-PDF-Word 全量抠图+抽文标出处；**CAD 与 3D 须客户导出件或外部渲染，不能直喂 AI**，缺件走拍板 #7）。

**M2 出口 / 交接闸（固化）**：科学顾问交付 **`scientist-报告.docx` ＋ `scientist-讲解.pptx`**（中间交付件，可上图）并**把报告写入对话** → 制片人把这两份文件交用户 → **报告审阅闸：等用户读完 → 明确回复「继续」**（意见记 `m2-纪要.md`，需修改/补充材料按用户答复回退）→ 收到「继续」→ 再做 **主题共识+内容重点对齐（KSP-03.5，用户圈选确认）** → **之后才进 M3 概念先行**。**未收到用户「继续」或主题共识未过，制片人与任何角色禁止进 M3 及任何后续环节/选项/拍板**（§5-10 / §5-18，流程见 `playbooks/science-report-flow.md`）。确认理解深度 ≥L2（否则查证或升级）；待确认项全部有去向。

### M3 创意概念先行（Insight→Ideation→Evaluation→Presentation→Refine；替代旧"概念先行（多方向）+评审"）
> **入口条件**：**报告审阅闸已通过（用户「继续」）+ 主题共识+内容重点对齐（KSP-03.5）已确认**，才启动本段；否则一律后置（§5-10）。
1. **Ideation（概念生成，并行 3-4 路）**：导演/编剧/摄影指导各出 **5 个创意概念**（不是完整方案！）——方法论 SIT/SCAMPER/TRIZ/Bisociation/换位/加减法/极端化；每概念=**大创意一句话+核心信息+风格基调(moodboard)+为什么成立（对接重点协议/受众/证据）+概念标题** → `concepts/`。
2. **Evaluation（评分）**：制片人+观众代言人按四维（预注册标准/传播力/科学准确/可执行，0-1）打分；红队（L 档）每概念 1-2 条挑战（含推翻条件）→ 排名表 `m3-scoring.md`。
3. **Presentation（概念拍板）**：概念卡并列全文展示 → `ask_user_question` 选一/融合/自定义（**#9 创意概念拍板**）。
4. **Refine（深化，只深化所选概念）**：导演整合各角色补位 → 完整方案 `m3-proposal.md`（定位/受众/**口播稿定稿**/分镜概览/执行计划）——**口播稿在方案里就定下来**（口播多方案拍板 #16：先定讲什么）+ `decision-log.md`（含被否概念与少数派报告）。
5. **九宫格出图（口播稿定后）**：按口播确定的内容/对象做**风格宫格**（宫格技法+美术批复）→ 用户拍板 #15 → **风格基线固化**写入分镜表表头（分镜/出图必须尊重基线，防同质化）。**顺序铁则：方案含口播稿 → 九宫格出图 → 分镜**。用户确认 ✅。

### M4 分镜 + 声音 + prompt（流水线 + 并行；输入=方案里的口播稿+风格基线）
1. **并行两路**（口播稿+风格基线均已在 M3 定）：
   - 分镜师 → 分镜表 → `storyboard-分镜表.md`（附：需要首帧图的结构清单、三视图需求）
   - 声音设计师 → 声音方案 → `sound-声音方案.md`（BGM 情绪曲线/音效清单/配音建议）
3. 摄影指导（等分镜表）→ 摄影方案 → `dop-摄影方案.md`（运镜/光影/拍法路线/参考资产需求，分镜表摄影扩展列）。
4. **prompt 工程（并行 fan-out）**：按口播/镜头自然分段（每段 5-8 镜），每段派生 1 个 prompt 工程师 → `prompt-<section>.md`；**逐镜写 prompt 按 `templates/prompt-sop.md` 十步**（取输入→定路线→选参考图[挂载清单→角色+部位+位置]→定主体→风格→时间轴→口播独立→负面[含广告禁用词]→参数→自检交付）；**十步不可跳**（跳=缺要素）；**交付文件必须严格统一**：每平台一个 `prompts-<平台>.md`（字段名/顺序/文件名/风格token 全按 `templates/prompt-sheet.md` 强制规范）；**交付前必须过两道机器门控**：`scripts/check_prompt_sheet.py`（格式与一致性）**＋ `scripts/check_prompt_sop.py`（十步执行证据：逐镜核对十步有没有留下产物证据——参考图裸引用/风格token不同源/口播≠口播稿/时间轴无分段=FAIL；缺"部位对应·放哪位置"/产品镜缺"保真实造型"/参数缺项=WARN）**。
5. **剪辑预计划（可与 prompt 并行）**：剪辑师 → `editor-剪辑预计划.md`（节奏/转场/字幕与图表层工作量）。
6. 美术指导复核 VI 合规（色板/字体/图表层规范）；分镜师+摄影指导合议运镜列定稿。
7. **科学顾问复核**（`subagent_fork` 或普通 subagent，只读 prompt 表+分镜+理解报告）：任何"待确认"表述进入 prompt 的，打回。
8. **红队前置闸**：只查硬性违规（科学错误/品牌禁区/审核红线/数据无出处）→ pass/fail；fail 打回相应段，循环 ≤2。
9. M4 出口按 `quality-gate.md` 清单自检 → 交用户确认。

### M5 制作交付 + 出口闸
1. 制片人陪用户用工作台出片（按 `playbooks/production-workflow.md` 逐步指导）。
2. 导演定剪意见（终审画面/声音/节奏，给出回炉清单）。
3. **红队出口闸**（独立 subagent，未参与创作）：只读全套制品+预注册标准，按 `quality-gate.md` 评分单产出 PASS/CONDITIONAL/BLOCK + 打回意见（≤2 次循环）。
4. 科学顾问终审全片表述；观众代言人最后过一遍脚本朗读版。
5. 用户签收 → 知识萃取（科学顾问 subagent 按 `kb/入库规则.md` + `kb/隐私红线.md` 执行）。

## 5. 硬规则

1. **子代理优先**：任何可归到角色的工作必须派角色 subagent，制片人不得包办（判定挂在**任务类型**上，不挂在工作量上；"很快/很简单"不是豁免理由）。
2. **📤 必带**：每个 worker 产出末尾必须有 `## 📤 传递给下游 (@制片人)` 块（`templates/handoff.md`）。
3. **分段落盘**：长文档每完成一节立即写盘；催办话术："请分段写盘"。
4. **文件名谁写谁定**：冲突时按 §3 规约，汇总文件只有制片人写。
5. **停滞检测（双账本）**：制片人维护任务账本+进度账本；连续两轮"无新论点/无制品改动/无标准更新"→ 机械判定停滞 → 重分解议题或升级用户，不许自由心证地继续。
6. **事实争议不折中**：查证或升级；已"待确认"的表述不得进入任何定稿。
7. **成本三档**：S/M/L 按 `DESIGN.md` §4 定档；M3 是全档唯一"值 15×"的点，每场会前自问"值不值"，不值就降级为裁决式。

32. **文字参考图（字帖）·字卡镜无帖不得开抽（硬规则）**：**来源＝红楼梦EP01·用户裁定 20260915**——裁定原文：「**凡画面要出现文字（谶语／回目／片名／落幅／玉面镌字／黑底字卡等），必须先做一张"文字参考图（字帖）"作为参考图挂载，让模型照抄字形；没有字帖的镜不得开抽。**」**成因**：模型对**未见过的繁体书法字形只能猜笔画**，成片**字形残缺／误出简体**；硬规则 #27 的"prompt 内逐字写明字形要求"只是**文字描述**，不解决"模型没见过这个字形"。**四条铁律**：①**字卡镜的参考组 ＝ 场景锚 ＋ 字帖（＋故事板）**——【参考】字段必须含 `@图片N=字帖-XXX.png（取字形→照抄该镜字卡文字）`，**缺字帖＝该字卡镜不得开抽**（与 #27 并列为前置件）；②**prompt 内逐字写明该文字并注「字形照 @图片N 的字帖」**——字卡落位句须写 `逐字照录「<文本>」共<N>字，字形照@图片N的〈字帖-XXX〉帖，一字不可增删改`；③**仍保留"逐字书写而出"的时间轴描述**——**字帖锁字形、时间轴锁笔迹生长**，两层并存（D10-d 不受影响）；④**字帖只锁字形，不得把字帖当画面底**——禁止当底图／底纹／贴图叠进画面（＝重蹈"字卡空版作废"的错）。**清单（逐条前置于出图）**：`runs/<slug>/m5-文字参考图清单.md`——逐条 `文本（逐字照录剧本原文，繁体/简体按原样、不得改写转写）｜用途（哪些镜/段）｜字形要求（碑刻楷/馆阁体/魏碑意/篆书）｜颜色（焦墨/朱砂/白）｜版式（竖排右1/3、叠角、玉面浮凸、黑底白字）｜出处（剧本行号或段号）`＋**单块 Image2 prompt（负面内嵌）**＋保存命名 `refs\锚图\字帖\字帖-<文本>.png`；**去重合并**（同一句多处出现者并为一帖，如"假作真時真亦假…"既作太虚对联又作落幅）。**统一规格**：`宣纸暖白底(#ece7d8)，竖排书法字帖，逐字清晰完整；无装饰无底纹无边框无印章无水印；字距匀整、笔画完整；繁体`＋负面 `简体字, 字形残缺, 错别字, 装饰纹样, 边框, 印章, 水印, 模糊`（**印帖**移除 `印章` 改钉闲章类；**原文即简体的条目**移除 `简体字` 改钉 `繁体字`，且**须上报拍板、禁静默混用简繁**）。**判废要点**：字形出简体／**缺笔**／**连笔糊**／错别字／结构被艺术化改写；出现**装饰边框／印章**（印帖除外）；**字帖被当底纹／底图用**；与剧本原文不一致（增删改字、简繁混用）；**字体串用**（玉面镌字应用馆阁体却用碑刻楷／印文应用篆书却用楷书）。**失败改法只有三种**：改措辞／改参考／重抽（**禁"后期修正字形"类表述**，承 #26 无后期原则）。动作／字卡细则见 `playbooks/animation-motion-design.md` **§4.3.1「字帖铁律」**；SOP 必含件见 `templates/prompt-sop.md` **必含件 6**；踩坑见 `knowledge/FAILURE-LIBRARY.md` **F-44**。

## 7. 全自动模式（用户说"全自动跑完"才用）

把 `orchestration/kesheng_workflow.js`（script 体）+ `orchestration/kesheng_workflow.meta.json`（meta）交给 DSH `workflow` 工具，`args` 传 `{ topic, runDir, platform, audienceMode, withCouncil }`。内部自动：M2 并行调研 → M3 概念先行（+可选红队评审）→ M4 口播→分镜→分段转写 fan-out → 出口红队闸。返回结构化摘要；**裁决与用户关卡仍由制片人执行**。

## 8. 降级规则（异常处理）

| 异常 | 处置 |
|---|---|
| 任务被判 S 档 / 用户要快速回答 | 制片人单干（原单机模式即降级版），交付时明示"降级模式" |
| subagent 派活失败/超时 | 同一子任务重派 1 次 → 仍失败则制片人接手该子任务，并注明降级 |
| 共享文件被并发写坏 | 按 §3 规约互不抢写；写坏时制片人用 `edit` 修复并重跑该段 |
| 用户中途要求"直接给结果" | 立即切 S 档单干，已有多 agent 产出择优保留 |
