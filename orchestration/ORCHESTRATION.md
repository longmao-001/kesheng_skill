# 🎬 科生编排手册（Orchestration Manual）

> 版本 v2.0 (2026-09)。制片人（主 agent）在 DeepSeek Harness (DSH) 里驱动科生团队**真多 agent 协作**的唯一操作手册。
> 编排底座与 Atelier 一致（`f:/AI/atelier/docs/DSH_ORCHESTRATION.md` 的同构版）；设计依据见 `docs/DESIGN.md`。

## 0. 术语与角色定位

- **制片人 = 主 agent（orchestrator）**：唯一"看得见全局"的角色。它**编排**，不亲自写内容（S 档除外）。
- **worker = 被派生的 subagent**：导演 / 编剧 / 分镜师 / 美术指导 / 摄影指导 / 声音设计师 / 剪辑师 / 科学顾问 / prompt 工程师 / 观众代言人 / 红队，各自独立上下文。
- **黑板 = 工坊目录**：`F:/AI/kesheng/runs/<项目slug>/`，所有 agent 的读写介质。项目 slug 用 `YYYYMMDD-主题缩写`（如 `20260901-基因编辑`）。

## 1. 工具映射（角色 → DSH 机制）

| 机制 | 工具 | 用途 | 科生用法 |
|---|---|---|---|
| 派生独立 worker | `subagent`（后台默认 true=并行） | 每个角色独立上下文、真并行 | M2 调研 / M3 盲提案 / M4 转写 |
| 继承上下文复核 | `subagent_fork`（后台默认 true） | 用下游角色视角复核上游制品 | 科学顾问复核 prompt 表；制片人复核争议条款 |
| 全自动扇出 | `workflow`（JS 多阶段+屏障） | 无依赖阶段的真并行、批量转写 | 用户说"全自动跑完"时：`orchestration/kesheng_workflow.js` |
| 人在回路关卡 | `ask_user_question` | 每里程碑停等用户确认 | M1/M3/M5 必用；M2/M4 出口按定档用 |
| 进度可视化 | `todo_write` | 里程碑/派活清单 | 开工即建，完成即更 |
| 制品读写 | `read` / `write` / `edit` / `glob` | 黑板读写 | 制片人汇总；worker 产出 |

## 2. 派活统一 prompt 模板（五段式，粘贴即用）

```
你被指派为「科生」团队的<角色>。你是独立上下文的 subagent——看不到本会话主对话，
只以黑板文件和本提示为事实来源。
开工三步:
  ① 用 read 工具读 F:/AI/kesheng/agents/<角色文件名>.md 作为你的角色卡，遵循其全部指令；
     再用统一知识图谱查你的 domain: python F:/AI/kesheng/packs/kg_query.py --domain <你的域> <任务关键词>
     （结果含实体属性+1跳邻居+权威正文路径；按结果 read 需要的原文，不要一次性全读）
  ② 读黑板: F:/AI/kesheng/runs/<项目slug>/brief.md (项目简报+预注册标准+档位)。
  ③ 读取上游📤: <上游制品文件路径>（若无则略过）。
任务: <一句话任务，含交付格式要求>
上游📤: <上游的"📤"块原文，未公开则写"盲提供案，不提供其他提案内容">
输出要求:
  - 完整产出写入 F:/AI/kesheng/runs/<项目slug>/<角色>-<制品>.md
  - 末尾必须有 `## 📤 传递给下游 (@制片人)` 块（格式见 templates/handoff.md）
  - 分段落盘：长文档每完成一节立即写盘，禁止憋单文件
  - 科学准确铁律：数据有出处；不确定标"待确认"；绝不编造
  - 知识沉淀：调研中新学到的通用知识追加到对应域片段 packs/<域>-kg/kg.json（带 sources），由制片人重建图谱；禁止新建 markdown 概念卡
  - 结尾附 3 行总结: 关键产出 / 置信度自评(高/中/低) / 需要制片人拍板的事
```

## 4. 里程碑派活清单（关卡式默认流程）

### M1 简报 + 约束清单（并行 4 路）
1. 制片人用 `templates/brief.md` 向用户调研 → 定稿 **预注册标准 + 档位(S/M/L)** → 写 `brief.md`。
2. 并行派生 4 个 subagent：
   - 科学顾问 → 一页**科学硬约束清单**（哪些表述必须精确/哪些禁止）
   - 导演 → **艺术基调**（导演阐述雏形：主题一句话/风格关键词/节奏方向）
   - 摄影指导 → 一页**可拍约束清单**（平台能力边界/拍法路线/风格禁区）
   - 观众代言人 → **受众证据模型**（受众消费场景/最先看的指标/证据可视化优先）
3. 制片人汇总进 `brief.md` → `ask_user_question` 请用户确认。

### M2 科学理解（fan-out 3-5 路，档位 L 可扩 5）
| 路 | 角色 | 方向 |
|---|---|---|
| 1 | 科学顾问 | 7 步深度理解法 → `scientist-理解报告.md`（含 L 等级自评+待确认清单） |
| 2 | 观众代言人 | 受众语境与证据映射（受众能看懂的数据点/真实素材清单） |
| 3 | 导演 | 艺术基调与可拍性调研（叙事节奏方向/全片气质/镜头语汇候选） |
| 4/5 可选 | 美术指导 / 编剧 | 风格方向调研（色板/VI 联想）/ 叙事角度初探 |

汇总：制片人读各 📤，确认理解深度 ≥L2（否则查证或升级）；待确认项全部有去向。**由用户确认后进 M3。**

### M3 创意概念先行（Insight→Ideation→Evaluation→Presentation→Refine；替代旧"盲提案×4+评审"）
1. **Ideation（概念生成，并行 3-4 路）**：导演/编剧/摄影指导各出 **1-2 个创意概念**（不是完整方案！）——方法论 SIT/SCAMPER/TRIZ/Bisociation/换位/加减法/极端化；每概念=**大创意一句话+核心信息+风格基调(moodboard)+为什么成立（对接重点协议/受众/证据）+概念标题** → `concepts/`。
2. **Evaluation（评分）**：制片人+观众代言人按四维（预注册标准/传播力/科学准确/可执行，0-1）打分；红队（L 档）每概念 1-2 条挑战（含推翻条件）→ 排名表 `m3-scoring.md`。
3. **Presentation（概念拍板）**：概念卡并列全文展示 → `ask_user_question` 选一/融合/自定义（**#9 创意概念拍板**）。
4. **Refine（深化，只深化所选概念）**：导演整合各角色补位 → 完整方案 `m3-proposal.md`（定位/文案结构/分镜概览/执行计划）+ `decision-log.md`（含被否概念与少数派报告）。
5. 用户确认 ✅ → **九宫格风格预览**（同旧 #7 步骤：宫格技法+美术批复+用户拍板 #15 → 风格基线固化写入分镜表表头，分镜与后续出图必须尊重基线，防同质化）。

### M4 分镜 + 声音 + prompt（流水线 + 并行）
1. 编剧（串行，等 M3 定稿 + 九宫格基线）→ 口播稿 v2 → `screenwriter-口播稿.md`；**制片人先用选项卡交用户拍板口播稿（#16，重要：影响分镜设计）→ 确认后才继续**。
2. **并行两路**（都以口播稿+风格基线为输入）：
   - 分镜师 → 分镜表 → `storyboard-分镜表.md`（附：需要首帧图的结构清单、三视图需求）
   - 声音设计师 → 声音方案 → `sound-声音方案.md`（BGM 情绪曲线/音效清单/配音建议）
3. 摄影指导（等分镜表）→ 摄影方案 → `dop-摄影方案.md`（运镜/光影/拍法路线/参考资产需求，分镜表摄影扩展列）。
4. **prompt 工程（并行 fan-out）**：按口播/镜头自然分段（每段 5-8 镜），每段派生 1 个 prompt 工程师 → `prompt-<section>.md`；**交付文件必须严格统一**：每平台一个 `prompts-<平台>.md`（字段名/顺序/文件名/风格token 全按 `templates/prompt-sheet.md` 强制规范），**必须通过校验脚本 `scripts/check_prompt_sheet.py <runs/<slug>>` 才能交付**。
5. **剪辑预计划（可与 prompt 并行）**：剪辑师 → `editor-剪辑预计划.md`（节奏/转场/字幕与图表层工作量）。
6. 美术指导复核 VI 合规（色板/字体/图表层规范）；分镜师+摄影指导合议运镜列定稿。
7. **科学顾问复核**（`subagent_fork` 或普通 subagent，只读 prompt 表+分镜+理解报告）：任何"待确认"表述进入 prompt 的，打回。
8. **红队前置闸**：只查硬性违规（科学错误/品牌禁区/审核红线/数据无出处）→ pass/fail；fail 打回相应段，循环 ≤2。
9. M4 出口按 `quality-gate.md` 清单自检 → 交用户确认。

### M5 制作交付 + 出口闸
1. 制片人陪用户用工作台出片（按 `playbooks/production-workflow.md` 逐步指导）。
2. 导演定剪意见（终审画面/声音/节奏，给出回炉清单）。
3. **红队出口闸**（独立 subagent，未参与创作）：只读全套制品+预注册标准，按 `quality-gate.md` 评分单产出 PASS/CONDITIONAL/BLOCK + 打回意见（≤2 次循环）。
4. 科学顾问终审全片表述；观众代言人最后过一遍脚本朗读版。
5. 用户签收 → 知识萃取（科学顾问 subagent 按 `kb/入库规则.md` + `kb/隐私红线.md` 执行）。

## 5. 硬规则

1. **子代理优先**：任何可归到角色的工作必须派角色 subagent，制片人不得包办（判定挂在**任务类型**上，不挂在工作量上；"很快/很简单"不是豁免理由）。
2. **📤 必带**：每个 worker 产出末尾必须有 `## 📤 传递给下游 (@制片人)` 块（`templates/handoff.md`）。
3. **分段落盘**：长文档每完成一节立即写盘；催办话术："请分段写盘"。
4. **文件名谁写谁定**：冲突时按 §3 规约，汇总文件只有制片人写。
5. **停滞检测（双账本）**：制片人维护任务账本+进度账本；连续两轮"无新论点/无制品改动/无标准更新"→ 机械判定停滞 → 重分解议题或升级用户，不许自由心证地继续。
6. **事实争议不折中**：查证或升级；已"待确认"的表述不得进入任何定稿。
7. **成本三档**：S/M/L 按 `DESIGN.md` §4 定档；M3 是全档唯一"值 15×"的点，每场会前自问"值不值"，不值就降级为裁决式。
8. **拍板选项卡（硬规则）**：任何用户拍板点用 `ask_user_question` 提交选项卡（≥2 选项、推荐置顶标"(Recommended)"、可多选、必留"自定义"兜底）；**对话中任何让用户选择的事项同样必须用选项卡，禁止纯文本列选项**；预置选项速查见 `templates/user-gate.md`，按项目实际改写选项文本；禁止开放式提问（信息枚举不了时才允许开放+兜底）。**证据先行**：基于项目文件的拍板必须先展示文件内容（文本贴全文/要点，图片给路径+描述+贴图，数据给来源）再给选项，禁止让用户盲选。
9. **知识一律入图谱（硬规则）**：任何 agent 的调研/验证/萃取得到的知识**只写入图谱**——追加到对应域片段 `packs/<域>-kg/kg.json`（或新建域片段）→ 跑 `scripts/build_union_kg.py` 重建；**禁止新建 markdown 概念卡/笔记**。现有 `knowledge/`、`kb/` 仅作为历史权威正文被 sources 引用，不再扩写。知识查询唯一入口 = `packs/kg_query.py --domain <域> <关键词>`。
10. **调研报告先读后谈（硬规则）**：每个新任务调研完成后，**第一步是把调研报告全文交给用户阅读并展开讨论**（开放对话，记录 `m2-纪要.md`）；**讨论完毕之前，不提供任何后续选项/拍板卡**（方案/风格/九宫格/口播稿等一律后置）。"两点讲明"（产品=介绍+卖点/机构=研究什么+人员组成/设施=能力+存在意义/科普=先讲人）随报告一并呈现。
11. **主题共识+内容重点先于方案（硬规则）**：出方案前必须①一句话主体共识（给用户确认/纠偏）②内容重点清单 3-8 条（与用户逐条讨论）③重点圈选（选项卡**多选**，用户侧重的加强/弱化/删除）④重点协议落 `brief.md`（重点×P0/P1×证据×镜头预算）——**协议未确认不出方案**；口播/分镜/时间轴按协议权重分配。
12. **字幕=口播逐句同步（硬规则）**：口播段的字幕就是口播的逐句投影（口播念什么字幕显什么，≤10 字/屏断行）；无口播段不设字幕，只允许信息卡/数据卡（数值+单位+出处）；**任何进成片的文字（字幕/字卡/落版）必须是口播稿原文、用户确认过的文案或数据卡**——禁止自创/改写/缩写（"稳了·不白测""量测·怕光源一抖"类事故）。依据：knowledge/ad-copy.md §二·五；编剧/分镜师/剪辑师/prompt 工程师/红队均按此执行与打回。
13. **文案白名单（硬规则）**：用户确认过的文案（口播/落版/slogan/字幕）是白名单；后续任何人不得擅改、不得新增"小发明"文案；新增必须经用户确认并更新白名单（写进 brief 口径纪律）。
14. **零意外·素材自包含（硬规则）**：交付件（方案/方案包/上手包）**自包含**——所有画面素材要么①已下载入包（含来源/授权）②附**文生图/图生视频生成 prompt**③取自已收集客户素材；**交付后用户再拍照/找物/补素材=流程事故**。交付前必须过**检察官五层检查**（Atelier 模式：每层独立上下文检察官，只看证据不听辩护）——L1 素材检察官（`check_asset_pack.py`+逐镜核对）/ L2 prompt 检察官（`check_prompt_sheet.py`（R1-R11 + R12）+ **`check_residual.py`（禁词残留全文扫描，防"旧表述回归"）** + 详细读 + **图文对位硬查**）/ L3 事实检察官 / L4 出口检察官（七维评分+三态）/ L4.5 总检察官（检查裁决书）/ L5 用户签收；检察官卡 `agents/inspector.md`。
15. **产物落盘纪律（硬规则）**：科生的一切工作产物（调研/素材/分镜/口播/prompt/媒体/交付/校验样例）**一律写入 `F:/AI/kesheng/runs/<项目slug>/`**；**禁止**写入会话工作区（`F:\AI\DS harness`）或 kesheng 根目录散落（含 `_media/` 之类临时目录）；临时/测试材料放 `runs/_tmp-*`，交付前清理；校验脚本（scripts/）与模板（templates/）除外。
16. **产品/设备镜头 prompt 硬规则（刻死，写产品类必守）**：产品/设备/科研仪器类**图片 prompt** 必须套 `templates/product-prompt-formula.md`（八段），**视频 prompt** 必须套 `templates/video-prompt-formula.md`（九段：参数/参考/风格/镜头/时间轴/主体/声音/口播/负面/强制约束）＋ `knowledge/image-gen-formulas.md`，并逐条过其**校验清单**。**五铁律（违反=打回）**：
   ① **产品展示＝干净／功能展示＝复杂**（外观/身份/材质/原理=留白多、单一主体；功能/性能/应用=加机制/结果/环境细节）。
   ② **绝不改造设备真实造型**（以参考图锁定真实几何/部件/logo/材质，只动布光/机位/背景/构图/加字；"保持真实造型=@参考图不变"必须写进【主体】与【强制约束】；禁任何造型改动/新增部件/歪曲比例/掉色）。
   ③ **参考图"标角色＋部位对应"写显式**（每张必写：标角色 `@图N 是主体（整机）／部件参考（散热鳍片＝主体鳍片）／场景参考（用于背景环境）／质感参考`；**若场景参考含主体则注明"图中<位置>的<主体>是主体，取该主体"**；＋部位对应 `参考图<部位X>＝主体<部位X'>`＋放哪位置）；图片节点参考上限 3 张/次，逐镜视频可更丰富；水印图/竞品图/团队合影/带商标原理图示=禁入镜、禁作参考喂模型。
   ④ **文字**：AI 直出的字写死+位置；**精确数据**（±0.2%/10000h/170–2500nm 等）生成后 `⚠️核对=手册原文`（错则重抽或改后期）——科学红线，数据必须=手册原文。
   ⑤ **无抽象词**（无"高级感/震撼/电影感"，换具体视觉事实）｜单镜≤2 运镜+变速（动感三来源）｜无霓虹/暖调洗墙/彩色渐变。


## 6. 全自动模式（用户说"全自动跑完"才用）

把 `orchestration/kesheng_workflow.js`（script 体）+ `orchestration/kesheng_workflow.meta.json`（meta）交给 DSH `workflow` 工具，`args` 传 `{ topic, runDir, platform, audienceMode, withCouncil }`。内部自动：M2 并行调研 → M3 盲提案（+可选交叉质询+红队）→ M4 口播→分镜→分段转写 fan-out → 出口红队闸。返回结构化摘要；**裁决与用户关卡仍由制片人执行**。

## 7. 降级规则（异常处理）

| 异常 | 处置 |
|---|---|
| 任务被判 S 档 / 用户要快速回答 | 制片人单干（原单机模式即降级版），交付时明示"降级模式" |
| subagent 派活失败/超时 | 同一子任务重派 1 次 → 仍失败则制片人接手该子任务，并注明降级 |
| 共享文件被并发写坏 | 按 §3 规约互不抢写；写坏时制片人用 `edit` 修复并重跑该段 |
| 用户中途要求"直接给结果" | 立即切 S 档单干，已有多 agent 产出择优保留 |
